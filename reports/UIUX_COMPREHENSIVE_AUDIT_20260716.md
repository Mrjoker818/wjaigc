## 已确认问题

### P0：画布自动保存形成持续写入循环，可能造成拖动画布卡顿

- 证据：浏览器会话中 `/api/user-data/record` 出现数千次成功 `POST`，并持续伴随 `projects` 同步请求。
- 根因：[`src/app/page.tsx`](../src/app/page.tsx:759) 的自动保存 effect 依赖 `currentProject`，定时回调又在 [`src/app/page.tsx`](../src/app/page.tsx:765) 调用 `setCurrentProject` 写入新的 `updatedAt`。这会使 effect 自身持续重新触发，约每秒重新保存和请求一次。
- 用户影响：画布处于空闲状态也会占用主线程、网络和存储；图片多时更可能出现拖动掉帧、点击冻结、云端同步争用。
- 修复方向：保存条件改为内容指纹或 dirty revision，`currentProject` 用 ref 读取；只在画布/项目数据实际变化后防抖提交，并合并同类 `record` 请求。

### P1：节点模式的“AI 建图”主入口无效

- 复现：桌面节点模式点击“AI 建图”，按钮呈现 active 状态，但没有弹窗、输入框或错误提示。
- 根因：[`src/components/node-editor.tsx`](../src/components/node-editor.tsx:819) 将 `aiBuildOpen` 的 state 值丢弃，只保留 setter；[`src/components/node-editor.tsx`](../src/components/node-editor.tsx:2239) 仍调用 `setAiBuildOpen(true)`，但组件中没有基于该 state 的渲染分支。
- 用户影响：自然语言建图是节点模式核心入口，当前完全不可用，且没有失败反馈。
- 修复方向：恢复受控 AI 建图弹窗，绑定 `aiBuildInput`、loading/error 和关闭逻辑；加入 UI 回归测试，断言点击后出现对话框。

### P1：智能对话 / Agent 在当前部署数据下不可执行

- 证据：第三方模型弹窗显示“还没有对话模型”，聊天模型 combobox 无可选值，发送按钮禁用；Agent 开关可以被点亮，但没有可用聊天模型执行其决策。
- 用户影响：界面让用户认为 Agent 已开启，实际不能完成对话、工具选择或任务执行。
- 归类：部署配置与模型数据完整性问题，不是本次前端布局修复引入。
- 修复方向：部署前校验至少存在一个 enabled chat model；没有模型时禁用 Agent 并显示可操作的配置入口，而不是仅允许切换状态。

### P1：节点模式在移动端不可用

- 复现：`390 x 844` 下进入节点模式。
- 证据：工作流工具栏横向裁切，左侧节点库与右侧属性区同时固定显示，中央画布几乎没有可操作宽度。
- 用户影响：手机上无法创建、查看或编辑工作流。
- 修复方向：移动端采用单列/抽屉式节点库和属性面板；工具栏改为可横向滚动或分组菜单，并在小屏默认关闭内容条与属性面板。

### P2：移动端右侧工作区的信息层级过密且顶部被侧栏遮挡

- 证据：移动截图中品牌标题左侧被浮动导航占用，聊天标签、模型、Agent、思考控件在窄宽度下挤压，信息密度过高。
- 已通过部分：右侧面板的展开/收起控制在本次修复后位于视口内，底部工具栏可横向访问。
- 修复方向：移动端右侧工作区改为底部抽屉或全屏页；顶部只保留主要 tab，二级控制放入溢出菜单。

### P2：多个图标按钮没有可访问名称

- 证据：节点模式的画布辅助按钮、属性区关闭/折叠按钮、内容条动作按钮在浏览器可访问性快照中显示为空 button；3D 展陈 Pro 标题栏最小化和关闭按钮也没有 `aria-label` 或 `title`。
- 代码例：[`src/components/display3d-panel.tsx`](../src/components/display3d-panel.tsx:669)、[`src/components/display3d-panel.tsx`](../src/components/display3d-panel.tsx:672)。
- 用户影响：屏幕阅读器无法理解动作，鼠标用户也缺少悬停提示；测试自动化定位不稳定。
- 修复方向：所有图标按钮补充明确 `aria-label` 和 `title`，并用 `aria-pressed` 标注开关状态。

### P2：模型列表存在重复且来源不够显著

- 证据：图像生成器和展陈 Pro 的下拉列表包含多个同名 `Gpt Image 2`、`Gemini`、`SDXL` 项。图像生成器有提供商后缀，展陈 Pro 列表只显示同名模型，容易选错实际供应商。
- 用户影响：无法可靠判断费用、能力和实际使用的 API 供应商，尤其会重现“界面选 Gemini、供应商显示 GPT Image”类困惑。
- 修复方向：以 `providerId + modelId` 作为唯一 UI 选项，展示供应商标签和协议能力；渲染前去重，提交后在任务卡展示实际 provider/model。

### P3：控制台仍有初始连接错误和项目同步警告

- 错误：`/api/task-events` connection reset、`/api/user-data/record` connection refused（均发生于本地服务器重启窗口）。
- 警告：`loadProjectsFromServer` 反复收到 `value: null`。
- 说明：这些错误不证明生产环境一定失败，但会掩盖真正的接口错误；需要在部署环境做一次冷启动、断网重连和数据库空值回归测试。

## 已验证正常的修复项

- 画布底部工具栏不再因 hover 展开导致点击目标横向跳动。
- 人物精修大师、图层面板、版本历史、画布图像生成器均可在桌面居中打开。
- 右侧工作区收起控制在 390px 视口内可点击。
- 3D 展陈 Pro 可以打开完整工作台，资产、场景、模型、输出区均有实际界面，生成按钮会在必填品牌信息缺失时正确禁用。
- 无限画布、节点模式、智能对话的基础界面没有发现运行时 React 崩溃。

## 修复优先级建议

1. 先消除项目自动保存自循环和写入风暴，再复测大画布拖动、选图、缩放、同步。
2. 恢复节点 AI 建图弹窗及提交链路，并加浏览器回归测试。
3. 为云端部署补齐聊天模型，给 Agent 增加配置前置校验。
4. 单独完成节点模式的移动响应式改造；在完成前，产品侧应明确工作流编辑仅支持桌面。
5. 统一图标按钮的可访问名称与 tooltip，并规范模型去重和供应商显示。
