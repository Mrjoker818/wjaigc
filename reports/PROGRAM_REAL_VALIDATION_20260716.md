日期：2026-07-16

## 结论

当前代码库可以通过生产构建，类型检查和自动化回归；无限画布、节点模式、独立智能对话页面均能在真实浏览器中加载。它尚不适合直接视作全功能可用版本：发现 1 项凭据泄露、1 项节点工作流保存故障，以及数项运行时配置和浮窗状态管理问题。

本报告不记录任何 API Key、余额密码或会话凭据。

## 已确认问题

### P0：匿名模型接口泄露供应商余额密码

- 入口：`GET /api/models?type=all`，匿名请求可访问。
- 实测：返回 10 个提供商，其中 2 个包含非空 `balance_password` 字段。
- 根因：`sanitizeProvider` 仅从 `ApiProvider` 中移除了 `apiKey`，其余字段被展开返回；`balancePassword` 未脱敏。
- 影响：任何匿名访问者都可获取用于供应商余额查询的密码，属于凭据泄露。
- 涉及代码：`src/lib/server-api-config.ts` 的 `sanitizeProvider`，`src/app/api/models/route.ts` 的公开返回。
- 修复方向：公开 DTO 应采用字段白名单，只返回 UI 必需的 id、名称、状态、模型及不含凭据的基础信息；同时要求登录态并按权限过滤提供商信息。

### P1：节点工作流保存固定回环到 5000 端口，当前运行端口为 5006 时必然失败

- 实测：节点文本执行成功后点击“保存”，浏览器收到 `/api/workflow/save` 的 HTTP 500。
- 环境：`DEPLOY_RUN_PORT` 未设置，当前服务实际运行于 5006。
- 根因：`src/app/api/workflow/save/route.ts` 内部请求硬编码为 `http://localhost:${process.env.DEPLOY_RUN_PORT || 5000}/api/user-data/sync`。
- 影响：在非 5000 端口的开发、预览或部分云端部署中，工作流无法保存或加载。
- 修复方向：直接调用共享数据存储层，或使用当前请求的 origin，而不是回环到固定端口。

### P1：普通管理员呈现管理菜单，但根管理员接口拒绝请求

- 实测：测试用户显示“管理员”及完整管理导航，但 `/api/admin/users`、`/api/admin/groups` 各出现两次 HTTP 403，浏览器控制台共 4 条错误。
- 根因倾向：UI 用 `role === 'admin'` 展示，部分 API 采用更严格的根管理员名称/身份检查。
- 影响：权限语义不一致，用户会看到无法真正操作的管理入口，并持续产生控制台错误。
- 修复方向：统一管理员定义，或明确隐藏根管理员专用入口，并在 API 调用前进行权限能力判断。

### P1：底部工具浮窗不是互斥状态，且关闭操作会被侧边面板遮挡

- 实测：语言修图浮窗按 Esc 未完全关闭，随后打开 Agent 后两个工具窗口同时存在；视频面板关闭按钮被右侧生成面板拦截，真实点击超时。
- 影响：浮窗叠加、无法关闭或焦点错乱，违反“中央单浮窗”的预期，影响画布工具可用性。
- 修复方向：建立单一 `activeToolDialog` 状态；所有工具入口统一关闭上一窗口；以可访问的“关闭”按钮和一致的 Escape 处理实现关闭；检查右侧面板与对话框的 z-index/pointer-events。

### P2：视频能力在当前环境不可用

- 实测：`/api/workflow/models?type=video` 返回 0 个模型；视频生成面板显示“请在管理员后台添加视频模型”，生成、AI 导演增强、分镜按钮禁用。
- 说明：前端禁用行为正确，但当前部署没有可运行的视频生成能力。

### P2：项目同步每 30 秒产生无效警告

- 实测：控制台持续出现 `loadProjectsFromServer: unsuccessful response { success: true, key: projects, value: null }`。
- 代码路径：`src/app/page.tsx` 每 30 秒调用 `loadProjectsFromServer`；`src/lib/user-manager.ts` 将空值视为异常并输出 warning。
- 影响：控制台噪声、无效请求；需确认尚未同步过项目时的空值是否应作为正常空状态处理。

### P2：本地 ONNX 无损放大不可用

- 实测：`/api/image/health` 报告 `upscale.onnx.available=false`，原因为“ONNX 模型目录不存在”；Sharp/Lanczos3 可用。
- 影响：所谓 AI/超分放大在当前机器退化为插值放大，效果和模型能力不等价。

### P3：模型列表存在重复项

- 浏览器图像模型下拉列表中可见多个重复的 GPT Image、Gemini、SDXL 项。
- 建议：按 `providerId + modelId` 做去重并在管理员配置层明确同名模型来源。

## 未执行的付费或外部操作

图像生成、视频生成、云端 3D 生成、AI 修图、商业精修、人物精修、展陈生成等会真实消耗第三方额度。本轮仅验证了入口、状态、参数控件与可执行前置条件，未提交实际付费任务。不能把“面板能打开”解释为这些外部服务已端到端成功。

## 建议修复顺序

1. 立即修复 `/api/models` 的 `balance_password` 泄露，并轮换已暴露的余额密码。
2. 修复工作流保存的固定端口回环，补充非 5000 端口集成测试。
3. 统一管理员能力判断与界面可见性。
4. 重构底部工具为单实例浮窗管理，补充 Escape、叠窗和点击遮挡 E2E 测试。
5. 配置视频模型与 ONNX 放大模型后，分别执行一次真实生成验收。
