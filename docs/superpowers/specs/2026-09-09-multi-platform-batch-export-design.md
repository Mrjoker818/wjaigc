# 多平台批量尺寸和命名导出设计

日期：2026-09-09
状态：已确认，待实施计划
目标分支：`main`
稳定分支：`stable`，只读且不得修改

## 1. 背景

无界已经具备统一 Skill 运行内核、AssetVersion、画布和节点模式结果投影，以及若干单图和 ZIP 下载能力，但尚未提供可复用的“多素材 × 多平台尺寸 × 统一命名”交付工作流。现有批量下载只负责收集文件，不能证明尺寸正确、来源可追溯、名称稳定，也不能从失败项继续执行。

本功能属于 Lovart 增量工作流，不复制 V5.8.8 整体架构，不建立第二套任务、资产或积分系统。CPU 只承担 Sharp 图片转换、清单生成和 ZIP 打包，不调用本地 GPU，也不默认调用远程生成模型。

## 2. 已确认方案

采用确定性 CPU 派生方案：从现有图片 AssetVersion 创建平台尺寸派生版本，生成 ZIP 与机器可读 manifest。原始素材不可覆盖；每个输出必须拥有独立 AssetVersion，并保留来源、平台、尺寸、命名和运行身份。

本工作流不调用 AI 模型，积分估价与实际扣除均为 0，但仍进入统一 Skill 任务、事件和审计体系。

## 3. 目标

1. 支持一次选择 1～20 个受管图片 AssetVersion。
2. 支持同时选择多个版本化平台尺寸预设。
3. 支持 `cover` 裁切填充和 `contain` 完整留白，不允许拉伸变形。
4. 支持透明 PNG，透明通道不得因转换丢失。
5. 每个成功输出创建可追溯的派生 AssetVersion，不覆盖原版本。
6. 输出安全、唯一、确定性的文件名，以及与 ZIP 内容逐项一致的 `manifest.json`。
7. 支持有限并行、取消、恢复、幂等重放、参数冲突和失败项重试。
8. 无限画布、节点模式和独立智能对话调用同一后端运行和结果版本。
9. 保留现有 21 个 Skills、画布下载、PSD/SVG、项目保存和工作区入口。

## 4. 非目标

- 不使用 AI 补画、内容重构或智能构图。
- 不调用远程图片生成或编辑供应商。
- 不修改原始 Asset、AssetVersion 或画布 Placement。
- 不把平台尺寸写死在 UI 组件中。
- 不建立独立任务表、独立积分流水或第二套资产存储。
- 不把画布专属 Skills 目录复制到独立智能对话页面。
- 不处理视频转码、音频或 3D 文件。

## 5. 用户输入

### 5.1 素材

- `sourceAssetVersionIds`：1～20 个当前用户、当前项目内可读的图片版本 ID。
- 服务端必须重新校验用户、项目、资产归属和 MIME，不信任前端 URL。
- 同一来源在一次运行中只能出现一次。

### 5.2 平台目标

- `targetPresetIds`：至少 1 项。
- 平台预设来自服务端版本化注册表，包含平台、用途、宽、高、格式建议、透明支持和启停状态。
- 首版覆盖常见社交帖子、故事/短视频竖版、视频缩略图、Pinterest 图钉和电商主图类别；具体尺寸由注册表维护，UI 不复制常量。
- 运行创建时冻结预设版本。管理员后续修改预设不得改变历史运行和 manifest。

### 5.3 适配策略

- `cover`：保持比例缩放并居中裁切到目标尺寸。
- `contain`：保持完整图片，以透明或指定颜色补边。
- `background`：`transparent` 或合法的 8 位十六进制 RGBA 颜色。
- JPEG 不支持透明；选择透明背景时服务端必须输出 PNG 或返回明确校验错误，不能静默白底化。
- 不提供 `stretch`。

### 5.4 命名模板

默认模板：`{project}-{asset}-{platform}-{size}-{index}`。

允许变量：

- `{project}`：项目安全名称
- `{asset}`：来源素材安全名称
- `{platform}`：平台代码
- `{usage}`：用途代码
- `{size}`：`宽x高`
- `{index}`：同组从 1 开始的稳定序号

命名器必须移除路径分隔符、控制字符、Windows 保留名和尾随点/空格，限制基础名长度，并用稳定后缀解决重名。用户模板不得生成目录穿越路径。

## 6. 平台预设注册表

平台尺寸属于可变化配置，因此使用服务端版本化注册表，而不是散落在组件中的常量。

每条预设至少包含：

```ts
interface PlatformExportPreset {
  id: string;
  version: number;
  platform: string;
  usage: string;
  label: string;
  width: number;
  height: number;
  recommendedFormat: 'png' | 'jpeg' | 'webp';
  supportsTransparency: boolean;
  enabled: boolean;
}
```

管理员只能通过受控接口启停或新建版本；不能原地篡改已被历史运行引用的版本。尺寸、像素和数量必须受服务端上限约束。

## 7. 运行与数据流

统一 Skill ID 为 `preset-multi-platform-export`，运行步骤如下：

1. **校验输入**：解析来源版本、平台预设、适配策略和命名模板。
2. **规划输出**：计算笛卡尔积、预计文件数、总像素和输出格式，超过预算则拒绝创建。
3. **读取素材**：通过 AssetService 和受控媒体读取器取得实际字节；远程来源遵循现有安全下载边界。
4. **有限并行转换**：使用 Sharp 处理图片，默认并发 2，服从取消信号和像素预算。
5. **质量检查**：重新读取输出 metadata，验证尺寸、格式、透明规则和非空字节。
6. **保存派生版本**：每个成功输出通过现有 AssetService 创建独立 AssetVersion，父版本为来源版本。
7. **生成制品**：创建 `manifest.json` 和 ZIP；失败项进入 manifest，但不伪造文件。
8. **投影结果**：画布、Workflow 和独立智能对话读取同一 DurableSkillOutput。

所有阶段进度必须来自实际完成数量，不能使用虚假定时进度。

现有 `SkillStepDefinition` 强制每一步绑定模型角色，无法准确表达零模型 CPU 步骤。实施时只做一项向后兼容的运行内核扩展：为步骤增加 `runtime: 'model' | 'local'`，旧步骤缺省为 `model`；`local` 步骤禁止 `modelRole`，由受控本地工具注册表执行，并固定估价为 0。不得使用虚假模型绑定绕过现有校验和计费。

## 8. AssetVersion 与 manifest

派生 AssetVersion 的 metadata 至少记录：

```ts
{
  schemaId: 'multi-platform-export-v1',
  runId: string,
  sourceAssetVersionId: string,
  presetId: string,
  presetVersion: number,
  platform: string,
  usage: string,
  width: number,
  height: number,
  fit: 'cover' | 'contain',
  outputFormat: 'png' | 'jpeg' | 'webp',
  outputFilename: string,
  requestDigest: string
}
```

`manifest.json` 必须包含 schema 版本、Run 身份、创建时间、冻结参数、成功文件、失败项、来源版本、派生版本、字节数、尺寸、MIME 和 SHA-256。ZIP 中每个成功文件必须有且只有一条 manifest 记录，manifest 不得引用不存在的文件。

ZIP 和 manifest 分别作为 `kind: 'document'` 的 AssetVersion 持久化，并通过结构化 DurableSkillOutput 保存两个版本引用，不能只存在于浏览器内存。浏览器下载失败后应能从运行历史重新获取同一制品。图片派生版本仍保持 `kind: 'image'`。

## 9. 幂等、取消与恢复

- 请求摘要由用户、项目、Skill 版本、规范化来源列表、冻结预设、适配参数和命名模板共同计算。
- 同一用户和幂等键、相同摘要返回原 Run；同键不同摘要返回冲突。
- 派生版本创建复用现有数据库幂等约束，恢复执行不得重复创建版本。
- 取消后不启动新转换；已经验证并持久化的结果保留，Run 标记为现有终态 `cancelled`，不能回滚成 `completed`。
- 恢复从数据库中已完成的输出继续，不能从零重做。
- “只重试失败项”必须创建可追溯的新尝试，复用成功版本，不覆盖原 Run 证据。

## 10. 部分成功与错误合同

运行允许保留部分成功结果，但不新增 `partial` 终态。存在未成功项时 Run 使用现有 `failed` 终态，结构化结果写入 `outcome: 'partial_success'`、成功版本和失败项；全部成功时才进入 `completed`。失败必须归类为输入无权访问、来源损坏、格式不支持、像素预算超限、转换失败、存储失败、制品打包失败或取消。

错误响应沿用全平台统一格式并包含 `requestId`、`code`、`message` 和 `retryable`。不能吞掉 Sharp、存储或资产服务错误；日志不得包含 Access Token、API Key、完整用户图片或敏感提示词。

如果 ZIP 打包失败，已创建的派生 AssetVersion 仍可在运行详情中单独下载，Run 不能伪装为完整成功。

## 11. 三工作区交互

### 11.1 无限画布

Skill 抽屉包含素材、目标平台、适配方式、命名、执行预览和结果六区。执行前显示文件数量、预计总像素、预计 ZIP 体积和积分 0。结果按平台分组，可单张下载、整组下载、查看来源版本并批量放入画布。

### 11.2 节点模式

使用统一 `ai-skill` 节点，不复制执行器。输入端接收图片版本集合；输出端提供派生版本集合、manifest 引用和 ZIP 制品引用。节点重跑必须遵守同一幂等和来源规则。

### 11.3 独立智能对话

独立智能对话不显示画布专属 Skills 目录。用户通过自然语言提出导出要求时，由对话层收集平台、适配和命名参数，再调用同一 Skill API。结果进入共享项目和资产历史，可下载或返回画布继续处理。

## 12. UI 约束

- 抽屉遵循现有底部工具栏和 Skill 视觉体系，不新增悬浮中央大窗。
- 平台选择使用复选列表，适配方式使用分段控制，背景使用颜色控件，命名模板使用文本输入。
- 375px 下所有文字、按钮和预览不得溢出或重叠。
- 执行中提供真实进度、取消入口和逐项状态；部分成功必须清楚区分成功与失败。
- 不用长等待、动画或“生成中”文案掩盖真实状态。

## 13. 安全与资源边界

- 每个来源都执行用户、项目和 AssetVersion 归属校验。
- 仅允许受支持的图片 MIME；不依据扩展名信任内容。
- Sharp 输入使用现有集中像素上限和安全读取器。
- 首版上限为 20 个来源、20 个目标、最多 100 个输出；超过任一上限直接拒绝。
- 单输出和整批总像素均设置硬限制；ZIP 设置文件数与总字节限制。
- 文件名在服务端二次净化，禁止绝对路径和 `..`。
- ZIP 不接受用户提供的内部路径。

## 14. 测试与验收

### 14.1 单元测试

- 平台预设版本解析与冻结。
- `cover`、`contain` 尺寸计算和透明背景规则。
- 命名模板、中文、保留名、重名和路径穿越。
- 输出规划、数量和像素预算。
- manifest 一致性和稳定排序。
- 请求摘要与幂等冲突。

### 14.2 集成与数据库测试

- 来源归属和跨用户隔离。
- 派生 AssetVersion 的父子关系与 metadata。
- 并发同键只生成一组版本和一个 ZIP。
- 中断恢复不重复写入。
- 部分失败、取消和失败项重试。
- 制品持久化后重新下载。
- 积分估价与流水均为 0，且不产生退款流水。

### 14.3 浏览器测试

- 无限画布、节点模式和独立智能对话调用同一运行并读取同一结果。
- 横图、竖图、方图、透明 PNG、中文名称和同名素材。
- 多素材、多平台、两种适配模式和批量放入画布。
- ZIP 下载、manifest 校验、刷新恢复和运行历史重新下载。
- Chromium、Firefox、WebKit 及 375px 布局。
- 失败时保存 screenshot、video、trace、console 和 network。

### 14.4 回归门禁

- 现有 21 个 Canvas/Workflow Skills 数量和身份不变。
- Simple Chat 独立目录边界不变。
- 画布下载、PSD、SVG、项目保存、刷新恢复通过。
- TypeScript、ESLint、全量测试、保护基线和生产构建通过。
- 云端 exact commit、真实 ZIP、manifest、AssetVersion 和刷新恢复取得证据后，才可登记为 CLOUD PASS。

## 15. 发布与回滚

先以默认关闭的功能标志部署到 `main` 测试环境。完成本地、隔离 PostgreSQL 和跨浏览器门禁后，再由 Coze 拉取 exact commit。云端只对测试账号启用，验证通过后扩大开放。

回滚只关闭预设和入口，不删除已生成 AssetVersion、manifest、ZIP 或历史运行。`stable` 始终不参与本阶段开发和测试。

## 16. 完成标准

以下条件全部满足才算完成：

1. 三工作区共享同一 Run、AssetVersion 和制品。
2. 所有输出尺寸、格式和透明规则由字节级检查证明。
3. manifest 与 ZIP 内容完全一致。
4. 原始版本未被修改，父子关系可追溯。
5. 幂等、冲突、取消、恢复和部分失败均有自动化测试。
6. 积分估价、扣除和退款均为 0。
7. 既有功能保护和全量门禁无回归。
8. 云端 exact commit 的浏览器证据齐全。
