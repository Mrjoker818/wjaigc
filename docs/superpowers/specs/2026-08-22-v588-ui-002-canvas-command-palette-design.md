# V588-UI-002 画布命令面板设计

## 目标

在不替换当前无限画布控制器、不删除任何入口、不改变任务与资产链路的前提下，为无限画布增加可搜索、可键盘操作的命令面板。该项仅吸收 V5.8.8 的叶级交互优点，所有业务动作继续调用当前 `InfiniteCanvas` 已验证的处理函数。

## 已确认边界

- 只修改 `main`，不触碰 `stable@52f7c601ed150769e15d06fb435c6e360e28c9e7`。
- donor `J:\无界云端0820` 保持只读，不复制其 Canvas 状态或控制器。
- 不在本项引入小地图、协作、供应商、任务、账务、持久化或 `asset-v3` 改动。
- 命令面板是叶组件；开关状态、选择状态、视图状态、工具互斥和命令动作均由当前父画布持有。
- 不删除或重命名现有底部工具栏按钮，命令面板只是额外入口。

## 方案比较

### 方案 A：原样复制 donor 组件和接线

优点是代码量少。缺点是 donor 使用自身的 `setToolState`、小地图和直接状态写入，会绕开当前 `activePointerToolRef`、工具会话互斥和视图控制器，因此拒绝。

### 方案 B：复用交互，按当前命令回调重实现

新增纯展示命令面板，父画布组装命令并传入回调。缩放、重置、网格、连线、图层/历史、选择和抓手均走当前处理路径。该方案风险最小，采用此方案。

### 方案 C：先建立全站命令注册中心

长期扩展性更高，但会同时影响无限画布、节点模式和智能对话，超出单叶吸收范围，也不符合本阶段 YAGNI，暂不采用。

## 组件与数据流

新增 `CanvasCommandPalette`，接收 `commands`、`theme` 和 `onClose`。组件只负责四通道检索、焦点、上下循环导航、Enter 执行、Escape/Ctrl+K 关闭、遮罩关闭及空结果展示。

`InfiniteCanvas` 持有 `commandPaletteOpen`，并从当前状态构建命令：重置视图、放大、缩小、切换网格、切换连线、选择工具、抓手工具、取消选择、打开/关闭图层、打开/关闭版本历史。图层与历史动作必须继续通过 `activateCanvasToolSession`/`closeCanvasToolPanels` 保证互斥。

`CanvasZoomCluster` 只新增 `onOpenCommandPalette` 回调和命令图标按钮，不持有开关状态。

## 键盘与可访问性

- 画布上下文按 `Ctrl+K` 或 `Cmd+K` 打开；已打开时同一快捷键关闭。
- 当事件来自 `input`、`textarea`、`select` 或可编辑区域时，不劫持快捷键，保护提示词与表单输入。
- 面板打开后输入框自动聚焦；`ArrowUp`/`ArrowDown` 循环选择，`Enter` 执行，`Escape` 关闭。
- 根面板使用 `role="dialog"`、`aria-modal="true"`、明确标题与命令列表语义；所有按钮保留文本标签和快捷键提示。
- 使用 `data-popup` 与 `data-command-palette`，避免画布滚轮、点击和键盘处理穿透。

## 错误与状态规则

- 空命令或无匹配项不执行任何回调，显示“没有匹配的命令”。
- 执行顺序固定为先关闭面板，再调用动作，避免动作打开的新面板被命令面板遮罩覆盖。
- 命令动作抛错时不吞异常；现有全局错误监控负责记录。
- 面板关闭后不保留查询词或选中索引，下次打开从完整列表首项开始。
