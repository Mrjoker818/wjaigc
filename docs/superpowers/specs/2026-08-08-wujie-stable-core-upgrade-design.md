> 计划编号：`WJ-STABLE-001`
> 状态：升级总纲已确认，等待阶段 0 实施计划审批
> 设计基线：Git `69ba94ef6bde041293ad9609ec76285d3e287a7f`
> 设计日期：2026-08-08
> 最近复核：2026-08-09

> 唯一规划事实源：`docs/superpowers/specs/2026-08-08-wujie-stable-core-upgrade-design.md`

## 1. 总目标

在完整保留无界现有功能、三个特色工作区和旧项目数据的前提下，建立共享稳定内核，使无界达到可持续迭代、任务可信、画布流畅、功能真实可用、升级可验证和故障可回退的商业级受控状态。

六项不可变结果：

1. 现有功能不得丢失或被无声隐藏。
2. 无限画布、节点模式和独立智能对话必须保留，并继续服务不同用户群体。
3. 三个工作区采用“完全互通”策略，素材、结果和上下文可以受控流转。
4. 所有编辑采用 A1 不可覆盖版本策略，原始素材不会被结果覆盖。
5. 核心任务、积分、退款、恢复和模型路由必须以持久化事实为准。
6. 未经本地、数据库、浏览器和云端真实验证的版本不得判定为正式可发布版本。

## 2. 当前判断与设计边界

当前无界是 Next.js 16、React 19、TypeScript、PostgreSQL 构成的模块化单体，具有多供应商生成、无限画布、节点工作流、独立聊天、图片编辑、视频、3D、PSD/SVG、专业业务面板、管理员和积分支付等广泛能力。

产品功能范围接近 L4，但公共架构、数据一致性、任务终态、跨入口复用和发布门禁仍处于约 L3.5。当前主要矛盾不是功能不足，而是功能增长快于公共内核和质量体系收敛。

本设计不做以下事情：

- 不全量重写无界。
- 不一次性更换无限画布引擎。
- 不以删除节点、工具或入口换取性能。
- 不在公共链路收敛前继续复制新的供应商调用实现。
- 不把视觉改版与业务架构迁移混成一次大提交。
- 不把供应商不可用直接归为程序缺陷，也不把程序参数错误归因于供应商。

## 3. 五大界面拓扑与产品边界

功能保护、测试矩阵和阶段验收必须完整覆盖以下五个一级产品界面：画布模式、节点模式、智能对话独立页面、管理员系统仪表盘和用户仪表盘。统一身份、公开分享、桌面端、连接器和运维属于横向支撑能力，必须纳入相关界面验收，但不得被误列为可替代五大界面的新产品主入口。

### 3.1 统一身份、入口与权限层

保护登录、注册开关、会话刷新、退出、入口选择、产品类型授权、用户组、模型授权和三个工作区的进入/返回流程。任何工作区、仪表盘或公开页面都不得通过中转登录页或错误工作区完成导航。

### 3.2 创作者项目仪表盘

保护并独立验收：

- 我的项目：创建、打开、重命名、单删、批量删除、回收与刷新恢复。
- 模板广场、资产库、使用统计和智能对话项目同步。
- 用户设置、密码修改、通知偏好、默认生成参数。
- 积分余额、明细、套餐、充值订单、订单状态和失败提示。
- 返回工作台、进入三个工作区和退出登录的直接导航。

项目数、图片数、对话数、任务数和积分数必须来自一致的数据口径，不能由页面各自推算出互相矛盾的统计。

### 3.3 管理员运营仪表盘

保护并独立验收：

- 运营总览、云端任务监控和生产就绪状态。
- 用户管理、批量删除、分组管理、产品权限和模型授权。
- 积分总览、模型定价、人工充值、扣减、退款和账务流水。
- 操作日志、用户操作与错误记录、筛选、处置和审计追踪。
- API 提供商、模型目录、协议验证、余额和真实连接测试。
- 数据管理、用户图片、项目与聊天数据一致性。
- 支付配置、收款审核、订单时间、回调、冲正和对账。
- 电商模板与公共资源管理。

管理员仪表盘不是附属页面，而是模型路由、权限、账务和线上治理的控制面；阶段 1 和阶段 5 都必须包含它。

### 3.4 三个创作工作区

#### 3.4.1 无限画布

面向视觉创作和素材组织用户，保留自由布局、图片组、参考图组、融图组、批注、图片工具栏、底部工具栏、专业面板、任务结果、历史和项目恢复。

#### 3.4.2 节点模式

面向专业工作流用户，保留现有节点类型、连线语义、AI建图、执行、素材引用、预设、导入、日志、撤销重做和工作流保存。

#### 3.4.3 独立智能对话

面向低门槛自然语言用户，保留普通对话、图片理解、附件、记忆、分享、模型比较、深度研究和 Agent。独立聊天与无限画布内聊天是不同入口，不能混淆页面、路由或数据口径。

#### 3.4.4 完全互通

三个工作区共享素材身份、素材版本和任务事实，但保留独立布局、交互和历史。跨工作区操作通过受控服务完成：

```typescript
sendVersionToWorkspace({
  projectId,
  assetVersionId,
  targetWorkspace,
  placementHint,
});

createDerivedTask({
  sourceVersionIds,
  targetWorkspace,
  operation,
  providerId,
  modelId,
  parameters,
});
```

目标闭环：

```text
智能对话生成
-> 发送到无限画布
-> 画布编辑产生新版本
-> 发送到节点模式
-> 节点处理产生新版本
-> 返回智能对话
-> 查看完整来源关系
```

### 3.5 公开交付面

保护聊天分享页、分享撤销与过期、充值订单页、支付跳转和二维码、结果下载、项目导出及公开访问的权限边界。公开页面必须在未登录情况下按设计工作，且不能泄漏私有项目、会话、令牌或内部错误。

### 3.6 本地无界与插件连接器

保护桌面设备、心跳、更新、资源中心、本地生成记录、云端备份上传/下载/删除，以及 DCC、Photoshop、Illustrator 等连接器的登录、健康检查、预检、模板和任务入口。桌面端和插件使用独立鉴权契约，但共享用户、素材、任务、权限和审计事实。

### 3.7 共享内容与运营支持面

保护公告、帮助、提示词模板、收藏、公共资源、品牌资产、工作流模板、Agent 模板、诊断导出、存储诊断、全局错误监控和客户端错误上报。这些能力统一登记 featureId，不得因不在主画布首屏而被视为可删除代码。

### 3.8 业务工具域完整边界

业务工具清单至少覆盖：图像生成与参考图、矢量、去背景、擦除、蒙版、调色、放大、裁切、扩展、多角度、批注、元素拆解、PSD、效果图反拆、美陈与展陈、视频、音频、3D、人物精修、精修引擎、品牌电商、品牌工厂、品牌 IP、Logo、包装、字境、表情、AI PSD、六面体、场景工作室、活动场地，以及 PDF、PPT、Word、Excel、思维导图和流程图生成。正式功能目录必须以实际代码扫描结果为准，并允许新增条目，但不允许静默减少条目。

## 4. 功能零丢失机制

### 4.1 受保护功能目录

现有页面、API、工具、按钮、菜单、节点类型、Agent 工具、创作者仪表盘、管理员模块、公开页面、桌面端、插件连接器和数据能力必须使用稳定 `featureId` 登记。例如：

```json
{
  "featureId": "canvas.image.remove-background",
  "name": "移除背景",
  "workspace": "canvas",
  "entrances": ["image-floating-toolbar", "image-context-menu"],
  "api": ["/api/image-edit"],
  "actions": ["removebg"],
  "resultKinds": ["image", "mask"],
  "preservesOriginal": true
}
```

发布候选与基线比较时，以下任一变化均阻止发布：

- `featureId`、入口、路由、节点类型或 Agent 工具减少。
- 创作者或管理员仪表盘标签减少，公开页面、桌面端或连接器路由消失。
- 按钮存在但事件未绑定，或打开错误面板。
- 权限范围意外缩小，普通用户看不到管理员已授权模型。
- 选择的供应商模型与实际提交路由不一致。
- 结果类型、原图保护或保存恢复语义被改变。

### 4.2 界面与项目基准

迁移前保存入口选择、创作者仪表盘、管理员仪表盘、三个工作区、公开页面、桌面端和插件连接器的全页证据；其中三个工作区还要保存工具栏、面板、右键菜单和节点类型截图，以及 DOM 入口、可访问性树和关键操作录像。

准备固定兼容样本：单图、100图压力、图片组、参考图组、融图组、批注、视频、3D、PSD、节点工作流、智能对话历史、失败和取消任务。每次迁移必须验证可打开、内容数量一致、媒体有效、位置一致、可继续编辑、可保存并再次打开。

### 5.1 统一项目


### 5.2 素材与不可覆盖版本

```typescript
type AssetKind =
  | 'image'

  | 'psd'

interface Asset {
```

单输入编辑有一个父版本，融图和多参考图可有多个父版本。失败、取消和超时任务不产生有效当前版本。迟到结果进入隔离记录，不覆盖终态或当前版本。删除工作区节点只删除引用，不直接删除素材。

### 5.3 工作区放置

```typescript
interface WorkspacePlacement {
  id: string;
  workspaceId: string;
  assetVersionId: string;
  entityType:
    | 'canvas-image'
    | 'workflow-input'
    | 'workflow-output'
    | 'chat-attachment'
    | 'chat-result';
  transform?: {
    x: number;
    y: number;
    width: number;
    height: number;
    rotation: number;
    zIndex: number;
  };
  metadata?: Record<string, unknown>;

```

素材有效性与画布坐标分离，避免节点移动影响原文件、删除一处引用误删其他入口、同一图片跨工作区重复上传，以及媒体失效被误表现为普通空白框。

### 5.4 旧项目兼容

使用版本化读取器，不做打开即破坏性转换：

```text
schemaVersion 1 -> LegacyProjectReader
schemaVersion 2 -> TransitionalProjectReader
schemaVersion 3 -> UnifiedProjectReader
```

旧项目原样读取；用户首次产生新修改时才写入新结构；转换失败继续使用旧读取器；没有通过固定旧项目样本测试前，不得删除旧字段或读取器。

## 6. 统一任务、模型与账务核心

### 6.1 模型能力目录

所有入口只通过 `providerId + modelId + capabilities` 获取模型能力，包括比例、尺寸、质量、数量、参考图、蒙版、视频时长、协议、同步或异步模式、输出格式和审核限制。UI 不直接理解 Pear、302、APIB、4S 等协议差异。

任务同时记录：

```typescript
requestedRoute: { providerId: string; modelId: string };
actualRoute: {
  providerId: string;
  modelId: string;
  fallbackReason?: string;
};
```

显式选择的路由不可在凭据或参数异常时静默降级到其他供应商。

### 6.2 数据库权威状态机

```text
created -> queued -> submitting -> processing -> persisting -> completed
             |          |             |             |
             +----------+-------------+-------------+-> failed/cancelled/timeout
```

禁止 `failed/cancelled/timeout -> completed`，禁止同一任务重复结算，禁止内存、SSE、轮询或前端状态覆盖数据库终态。取消和超时必须向底层工作发出 `AbortSignal`；迟到结果只能记录，不能复活任务。

### 6.3 多图逐张返回

一次用户操作对应一个批次，每张图片是独立槽位和任务：

```typescript
interface GenerationSlot {
  slotIndex: number;
  taskId: string;
  status: TaskStatus;
  assetVersionId?: string;
  error?: UnifiedError;
}
```

供应商每完成一张，立即持久化并创建版本，通过 SSE 回填对应槽位；其他槽位继续运行。不得等整批全部完成后统一返回，也不得把多个供应商任务折叠为一个前端结果。

### 6.4 幂等与积分

任务创建、扣费、退款和重复请求使用 PostgreSQL 原子规则。幂等键至少绑定 `userId + idempotencyKey + requestDigest`；同键同请求返回同一任务，同键不同请求返回冲突。退款根据数据库最终终态执行一次性状态转换，不依赖组件或进程内 Map。

### 6.5 统一错误契约

```typescript
interface UnifiedError {
  code: string;
  message: string;
  source: 'client' | 'wujie' | 'provider' | 'database' | 'storage' | 'network';
  providerCode?: string;
  httpStatus?: number;
  retryable: boolean;
  requestId: string;
  taskId?: string;
  userAction?: string;
}
```

界面区分供应商审核拒绝、模型参数不支持、无界组装错误、网络中断、云端超时但上游仍执行、存储失败、积分不足和模型未授权。不得再使用浏览器原生弹窗暴露供应商原始 JSON。

## 7. 无限画布与 Agent 内核

### 7.1 画布职责拆分

保持现有渲染和功能，逐步拆分为：

```text
Canvas Renderer
Viewport Controller
Selection Controller
Canvas Commands
History Controller
Task Projection
Project Persistence
Tool Registry
Tool Session
Feature Panels
```

每次只抽取一个职责并保留行为测试，不同时修改无关 UI 或业务链路。画布和节点模式共享业务命令与素材版本，不强制共享渲染引擎。

### 7.2 共享 Agent 运行时

普通对话、画布聊天和节点 Agent 使用同一执行内核，通过不同上下文适配器接入。Agent 只能调用受控工具：

```text
list_project_assets
inspect_asset_version
create_generation_task
create_edit_task
send_version_to_workspace
create_workflow_from_intent
run_workflow
get_task_status
cancel_task
```

每个工具具备权限和模型授权检查、参数校验、幂等键、积分预估、确认边界、取消信号和审计记录。Agent 不直接修改工作区内部 React 状态。

## 8. UI、交互与动效系统

### 8.1 设计原则

UI 升级不是全量换皮，而是建立统一、可预测、可访问、可回归的交互内核。三个工作区保留各自密度和操作方式，共享设计令牌、图标、表单、弹窗、任务反馈和错误规范。

优先级：

```text
功能可用与状态可信
> 交互效率与布局稳定
> 可访问性与响应式
> 视觉一致性
> 非必要视觉特效
```

### 8.2 工具栏和面板

- 底部工具栏使用贴合底部的抽屉式工具面板，支持分类、搜索、最近使用和固定工具。
- 图片浮动工具栏根据可用空间自动翻转、压缩或分页，不超出视口、不被侧栏遮挡。
- 图标与名称居中对齐，统一图标尺寸、44px 最小点击区和至少 8px 间距。
- 使用 Lucide 图标和工具提示，不用文字圆角块替代熟悉图标。
- 面板统一标题栏、关闭、折叠、拖动、最小化、恢复和焦点行为。
- 禁止卡片嵌套卡片；工具面板保持紧凑、工作导向，避免营销式大标题。
- 模型选择后，只显示该模型真实支持的比例、尺寸、质量、数量和时长。

### 8.3 状态与反馈

统一展示排队、提交、生成、上传、逐张完成、失败、取消、超时、退款和重试。错误靠近触发位置显示，同时保留 `requestId` 和可执行动作。所有按钮有默认、悬停、按下、焦点、加载、禁用和错误状态。

### 8.4 动效边界

必要动效用于解释状态和空间关系：

- 抽屉和面板切换：150-240ms。
- 工具选中：颜色和背景状态变化。
- 素材跨工作区发送：短暂空间连续提示。
- 拖放落点：明确目标高亮。
- 节点执行：受控流向和阶段进度。
- 多图任务：每张结果独立回填。

禁止大面积粒子、持续背景动画、昂贵模糊滤镜、所有按钮弹跳、阻塞操作的过场、通过动画宽高引发布局重排。支持 `prefers-reduced-motion`；低性能和高节点场景自动降低非必要动效。

### 8.5 UI 发布门禁

- 受保护入口保留率 100%。
- 工具按钮绑定率 100%。
- 1366x768 和 1920x1080 不错位、不遮挡、不叠加、不超出视口。
- 键盘焦点、Escape、返回和关闭行为正确。
- 无浏览器原生业务错误弹窗。
- 动效不导致画布明显掉帧。
- Chromium、Firefox、WebKit 视觉和交互回归通过。
- UI 变更不得改变模型路由、任务数量、积分或保存语义。

## 9. 八阶段实施路线

实施顺序固定为阶段 0 到阶段 7。除 P0、安全泄漏、错误扣费、数据损坏和生产完全不可用外，不得跨阶段插队。每阶段只交付可独立验证的垂直切片，系统必须始终可运行、可回退。

### 阶段 0：五大界面基线与版本收口

保护并独立验收五个一级产品界面：

1. 画布模式。
2. 节点模式。
3. 智能对话独立页面。
4. 管理员系统仪表盘。
5. 用户仪表盘。

确认 GitHub、本地和云端提交一致；建立功能矩阵、API 清单、数据库依赖、界面证据、旧项目样本、真实用户旅程、性能基线和 P0/P1/P2 缺陷台账；整理补丁和未提交文件；暂停新增大型业务功能。

完成标准：能明确回答运行 Commit；五大界面每项功能有唯一 `featureId`、入口证据、真实结果和状态结论；核心流程包含正常、失败、刷新恢复和连续第二次操作；不再靠历史对话或按钮可点击判断可用性。

### 阶段 1：共享任务、模型、账务与错误核心

统一模型能力、`providerId + model` 精确授权、供应商适配、任务状态、逐张回图、SSE/轮询降级、取消超时、幂等、扣费退款、错误归因、刷新恢复和操作日志；同步接通管理员模型控制面、任务监控、模型定价和账务审计。

完成标准：`n=1/2/3/4` 真实通过；每张独立返回；终态唯一；同一幂等请求只扣一次；失败和取消只退款一次；PostgreSQL 并发测试通过；画布、节点和智能对话共享同一任务事实。

### 阶段 2：统一项目、素材与版本图

建立版本化 `Project`、`Asset`、`AssetVersion` 和 `WorkspacePlacement`；实现画布、节点、智能对话之间发送资产并保留来源；补齐跨设备同步、回收站、孤立媒体处理、空白图片框修复、旧项目读取器和向后兼容迁移。

完成标准：旧项目可原样打开；首次新修改才写入新结构；刷新、换设备和跨工作区传递不丢资产、来源、分组、连线或任务归属；迁移失败可回到旧读取器。

### 阶段 3：画布模式稳定内核

保持现有画布产品形态和全部工具入口，按顺序抽离 Viewport Controller、Selection Controller、Canvas Commands、History Controller、Task Projection、Project Persistence、Tool Registry 和 Tool Session；增加可见区域裁剪、分级图片加载、解码缓存与性能测量。

完成标准：平移、缩放、拖动、多选、框选、50 步撤销重做、刷新恢复、任务投影和工具退出清理均通过；100 节点平均不低于 55 FPS，300 节点不低于 45 FPS；不整套替换主画布引擎。

### 阶段 4：节点模式稳定化

保留节点模式独立入口和工作流产品定位。先建立受控验证层，再逐步加固节点、端口、类型化连线、视口、选择、自动布局、DAG 执行、上游等待、节点级重试、执行快照、取消恢复、日志和旧工作流兼容。任何采用 XYFlow/React Flow 的方案必须先通过数据与交互兼容实验，不直接整体迁移。

完成标准：旧工作流可打开和执行；100 节点拖动不低于 55 FPS，300 节点缩放不低于 45 FPS；50 步撤销重做正确；刷新后执行状态可恢复；无效连线在执行前被阻止。

### 阶段 5：智能对话独立页面稳定化

保留独立页面，不降级为画布侧栏。统一 SSE 增量解析、会话与任务状态、消息持久化、Skills、智能体、记忆、附件、图片/品牌/模型引用、工具调用、失败恢复和跨设备同步；完成生成资产向画布、节点发送，以及来源回溯。

完成标准：流式响应不重不漏；中断可恢复；重复提交不重复扣费；100 条消息滚动稳定；会话切换不超过 500ms；旧会话可读取；资产发送到画布和节点后身份与来源一致。

### 阶段 6：管理员与用户仪表盘加固

管理员仪表盘独立闭环用户、权限、供应商、模型、积分、定价、订单、支付、操作日志、数据管理、运营统计、系统设置和服务健康。用户仪表盘独立闭环项目入口、资产、积分余额、充值订单、交易明细、个人设置和三个创作入口。两套仪表盘共享业务数据，不共享杂乱 UI 状态。

完成标准：管理员统计与数据库真实数据一致；权限和模型授权不可绕过；支付、回调、冲正和对账幂等；用户项目与资产跨设备一致；五大界面导航、登录、退出和会话超时均通过。

### 阶段 7：业务工具逐项达到优级

按以下固定顺序逐个形成完整用户旅程，不并行铺开多个半成品：

1. 图像生成、参考图组、融图组、多图逐张返回和供应商能力约束。
2. 去背景、擦除、蒙版、调色、放大、裁切、扩展、多角度和批注。
3. 视频生成、视频编辑、音频和连续镜头。
4. 3D 生成、预览、后处理和下载。
5. 元素拆解、Pear 图层、PSD、矢量、AI PSD、效果图反拆和美陈展陈。
6. 人物精修、精修引擎、品牌、Logo、包装、字境、表情、场景与活动场地。
7. PDF、PPT、Word、Excel、思维导图、流程图及导出下载。
8. 公开分享、桌面端、备份更新、Photoshop/Illustrator/DCC 连接器、诊断和运维。

每项必须覆盖正常、供应商拒绝、超时、取消、重试、退款、保存恢复、连续第二次操作、三工作区传递和三浏览器回归。只有真实业务结果满足契约时才可标记通过。

## 10. 测试和性能门禁

### 10.1 六层测试

```text
L1 静态产品契约
L2 单元测试
L3 组件与交互测试
L4 API与PostgreSQL集成测试
L5 Chromium/Firefox/WebKit真实浏览器E2E
L6 云端真实供应商、对象存储和账务验收
```

本地编译、Lint、单元测试或 HTTP 200 都不能代替真实业务成功。缺少 PostgreSQL 隔离测试库或真实供应商条件时，相关项必须标记“未验证”或“阻塞”，不能标记通过。

### 10.2 登录保护

每次候选版本都验证入口、正确登录、刷新保持、三个工作区进出、退出、错误密码、会话超时和鉴权接口超时。任何“正在验证身份”永久卡住或登录入口失效均阻止部署，即使改动看似与登录无关。

### 10.3 性能目标

无限画布：空画布 2 秒内可交互；缓存项目 3 秒内打开；100 节点平移平均不低于 55 FPS；300 节点不低于 45 FPS；拖动和缩放输入延迟 P95 不高于 50ms；图片消失帧和不可点击时间均为 0；保存主线程阻塞不超过 100ms。

节点模式：100 节点拖动不低于 55 FPS，300 节点缩放不低于 45 FPS，500 节点无持续冻结，100 节点自动布局不超过 1 秒，50 步撤销重做正确。

智能对话：2 秒内可交互，100 条消息滚动稳定，切换会话不超过 500ms，Agent 首次进度反馈不超过 1 秒，附件上传不阻塞输入。

### 10.4 全阶段横向质量门禁

以下要求横跨阶段 0-7，不能推迟到最终发布时一次补做：

1. **安全与数据隔离**：验证鉴权、权限、用户/项目/素材归属、IDOR、XSS、CSRF、SSRF、上传 MIME 欺骗、路径穿越、Webhook 签名、速率限制和敏感日志脱敏。普通用户、管理员、公开访客、桌面端和连接器分别使用最小权限契约。
2. **数据库与迁移**：每次表或字段变化具备迁移、回滚、旧数据读取和隔离 PostgreSQL 验证；并发幂等、条件式终态、账务唯一性和事务补偿必须使用真实数据库测试。
3. **对象存储与媒体生命周期**：覆盖上传、持久化、校验和、受控读取、下载、过期 URL、孤立文件、删除引用、回收站和恢复；禁止把失效媒体静默表现为正常空白框。
4. **可观测性与隐私**：前后端日志贯穿 `appVersion`、`gitCommit`、`sessionId`、`requestId`、`taskId`、provider、model、duration、status 和 errorCode；不得记录密码、完整 Token、API Key 或用户私有图片内容。
5. **环境与部署**：开发、测试、Coze 预览和生产分别执行 doctor、环境变量、数据库、存储、CORS、Cookie、静态资源、Source Map、反向代理超时和供应商连通检查。运行 Commit 不可确认时禁止验收。
6. **可访问性、响应式与语言质量**：键盘、焦点、语义标签、对比度、`prefers-reduced-motion`、1366×768、1920×1080 和至少一个移动视口均须验证；用户界面默认使用准确中文，不暴露内部代码或未经整理的供应商原始错误。
7. **并发与多端一致性**：覆盖重复点击、双标签页、同账号多设备、刷新、离线重连、WebSocket/SSE 中断、旧请求迟到和并发保存，不得出现旧状态覆盖新状态、重复任务或重复结算。
8. **依赖与第三方合规**：执行依赖漏洞、许可证、供应链和密钥扫描；引用 Infinite Canvas、ASUI Canvas、RemoveBG、Recraft 等外部实现时记录版本、许可证、接口条款和可替代方案，不以未核实的参考代码直接替换生产能力。

任何一项缺少真实条件时标记为“未验证”或“阻塞”，不得由编译、Mock 或静态阅读替代。

## 11. 发布、回退与治理

### 11.1 固定发布顺序

```text
本地修改和完整验证
-> 提交并推送 GitHub
-> 记录 Commit SHA
-> Coze 部署标签页拉取和构建
-> 确认运行 Commit
-> 强制刷新和健康检查
-> 核心冒烟
-> 真实供应商与账务验证
-> 发布结论
```

云端临时修复必须回写 GitHub。不得在 Coze 对话框中把临时代码当正式部署，不得在未确认 Commit 时开始版本验收。

### 11.2 回退

保留 `current` 和 `previous-stable` 两个已验证版本。功能迁移使用 `legacy`、`core-v2-shadow`、`core-v2` 开关。任务保存 `handlerVersion`，旧任务继续由旧处理器解释。数据库优先只新增表和字段，破坏性删除至少延后一个稳定周期。

### 11.3 需求和缺陷治理

需求分为 `CORE`、`BUG`、`ENH`、`NEW`、`RESEARCH`。只有 P0、阻塞当前阶段的 P1、云端无法启动、登录完全不可用、数据迁移风险、安全泄漏和错误扣费允许插队。其他问题登记后进入对应阶段。

缺陷状态：

```text
发现 -> 待复现 -> 已复现 -> 根因确认 -> 测试已建立
-> 修复中 -> 本地通过 -> 云端待验 -> 云端通过 -> 已关闭
```

同一问题再次出现时重开原缺陷并标记“回归”，分析原测试为何未拦截。

### 11.4 文档事实源

- 本升级文档：升级目标、五大界面边界、阶段顺序、门禁和验收标准的唯一事实源。
- 仓库其他正式文档：工程事实、API 契约、测试记录和发布报告；发生冲突时必须回到本文件处理偏移。
- GitHub：Commit、分支、CI、Release 和 Tag。
- 对话：协作过程，关键决定必须回写本文件或对应正式文档后才生效。

优先级：当前用户明确决定 > 本升级文档 > 已确认专项设计和实施计划 > 当前代码与新鲜测试证据 > 历史文档和历史对话。

旧报告如果与后续真实证据冲突，只作为历史证据，不能作为当前发布结论。例如旧 `docs/testing/RELEASE_READINESS_REPORT.md` 的“可投入生产”判断已被后续缺陷与未闭环验证推翻。

## 12. 阶段完成和最终成功标准

单个阶段只有在代码任务、功能保护、本地测试、P0/P1、旧项目、性能、云端 Commit、真实浏览器、真实供应商、账务证据、文档同步和回退方案全部满足后，才可标记完成。受外部条件阻塞时只能标记“有条件完成”。

最终成功要求：

- 受保护功能和旧项目兼容率均为 100%。
- 五大界面的受保护入口、数据口径和导航链路均通过。
- P0 和 P1 为 0。
- 无永久生成中、重复扣费退款、恢复风暴、登录卡死和持续空白框。
- 画布模式、节点模式和智能对话独立页面完整互通并保留来源关系。

- 安全隔离、迁移回滚、对象存储、可观测性、环境部署、无障碍、多端并发和第三方合规门禁通过。
- 每个修复有永久回归测试，部署 Commit 可追踪，具备可执行回退。
