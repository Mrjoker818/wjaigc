# 智能对话模型选择与历史图片上下文加固设计

## 背景

V588-CHAT-001 的严格 SSE 解析已在 `main@2e04349a29e0d500132888215d0461c81cf09c29` 完成本地回归，并已部署到 Coze 云端。线上实际脚本包含 `SIMPLE_CHAT_SSE_MALFORMED`，证明新构建已生效。

云端真实浏览器验收继续发现三个独立缺陷：

1. 点击对话模型菜单中的 `Gpt 5.5` 后菜单关闭，但按钮和 `aria-selected` 仍停留在 `Gemini 3.1 Flash Lite Preview`，模型与供应商选择没有形成可验证的持久状态。
2. 纯文本消息会自动携带最近三轮用户消息中的历史图片。历史消息包含损坏或过期的 base64 图片时，APIMart 返回 `decode base64 image data failed`，导致与图片无关的纯文本对话失败。
3. 对话内容较多时，聊天模型和图像模型下拉列表会被消息内容覆盖。当前版虽然把菜单自身设为 `z-[100]`，但顶部栏丢失了父级层叠上下文，子元素的高层级无法稳定越过消息区。

V5.8.8 只读参考版本包含相同的模型菜单状态写法与历史图片自动携带逻辑，因此不能直接吸收这两项数据流修复；但它已恢复顶部栏的 `relative z-50` 层叠上下文，可作为下拉列表遮挡问题的精确 donor。该修复最初来自提交 `01e45fbf`，随后当前线在恢复提交 `69ba94ef` 中回退，属于已定位的历史回归。

## 目标

- 模型选择必须原子更新 `modelId + providerId`，并在界面、任务持久化和下一次请求中保持一致。
- 聊天模型和图像模型下拉列表必须始终显示在消息内容之上，并保持可滚动、可点击。
- 保留多轮图片上下文能力，但只携带结构有效、可安全提交的图片引用。
- 无效历史图片不能阻断纯文本请求，也不能被静默当成有效图片发送给供应商。
- 不重构独立智能对话页面布局，只恢复顶部栏必要的层叠上下文；不修改管理员供应商配置，不触碰 `stable`。

## 非目标

- 不增加新的模型选择 UI、图片上下文开关或供应商自动切换。
- 不改变 APIMart、PearAPI 或其他供应商的模型可用性。
- 不处理供应商返回的 `get_channel_failed`；该错误继续按真实供应商错误展示。
- 不重构整个 `chat-area.tsx`，不改变 CanvasEditor、Deep Research 的产品行为。

## 设计

### 1. 原子模型选择

新增一个无副作用的模型选择状态单元，以 `{ modelId, providerId }` 为不可分割的值。菜单项只调用一个选择动作，不再分别写入两个可能不同步的状态。

选择动作必须同时完成：

1. 更新当前界面显示。
2. 关闭对应模型菜单。
3. 将同一模型与供应商组合写入当前任务。
4. 后续普通对话、CanvasEditor 和 Deep Research 请求从同一选择快照读取参数。

任务切换时只接收新任务的模型组合；当前任务因持久化产生对象更新时，不得把刚选择的新组合覆盖为旧值。

### 2. 历史图片上下文筛选

抽取纯函数构建最近图片上下文。输入为历史消息，输出包含：

- 可提交的最近图片；
- 被过滤的图片数量；
- 参与上下文的消息 ID。

仅接受以下输入：

- `http://` 或 `https://` URL；
- 受控站内绝对路径，例如 `/api/serve-upload/...`；
- `data:image/...;base64,...`，且 MIME 属于允许的图片类型、base64 可解码、解码后非空。

拒绝空字符串、`blob:`、非图片 data URL、格式损坏的 base64、普通文本和不受支持协议。远程 URL 的在线可达性仍由后端安全下载和供应商链路验证，前端不增加逐图预请求，避免额外延迟和跨域问题。

最近三轮规则保持不变，但每轮只发送通过筛选的图片。当前用户本次明确上传的图片也必须经过同一结构校验；无效输入应在提交前给出明确错误，不发送请求。历史无效图片则从本次请求排除，并显示一次非阻断提示。

### 3. 模型菜单层叠边界

选择性吸收 V5.8.8 的最小修复：顶部栏恢复 `relative z-50`，让模型菜单的绝对定位和层级在明确的父级 stacking context 中生效。消息滚动容器继续保持原有结构，不使用 Portal，不修改菜单尺寸、视觉样式或交互入口。

该修复同时覆盖聊天模型与图像模型菜单。验收不能只检查 class 字符串，还必须在长对话场景验证：

- 菜单像素区域位于消息内容之上；
- 菜单项可点击，点击目标不被消息元素截获；
- 菜单内部滚动正常；
- 桌面常用分辨率和移动端窄视口不存在顶部裁切或横向溢出。

### 4. 请求一致性

普通对话、CanvasEditor 和 Deep Research 在请求开始时捕获一次模型选择快照。请求体、消息记录中的模型信息、重试上下文和任务持久化均使用该快照，禁止在异步过程中重新读取可能变化的旧闭包状态。

历史图片筛选结果只影响发送给 `/api/simple-chat/chat` 的 `messages[].images`，不删除或改写用户历史记录。用户仍可查看旧图片；修复不会破坏已有会话数据。

### 5. 错误处理

- 当前上传图片无效：阻止提交并显示可理解提示。
- 仅历史图片无效：继续发送纯文本或其余有效图片，并提示已忽略失效历史图片。
- 供应商通道失败：保留供应商错误码和 requestId，不改写为 SSE 协议错误。
- 严格 SSE 解析失败：继续使用 V588-CHAT-001 已实现的 `SimpleChatSseProtocolError`。

## 测试设计

先建立失败测试，再写生产代码：

1. 模型选择纯函数一次返回正确的 `modelId + providerId`。
2. 从 Gemini 切换到 GPT 后，按钮、`aria-selected`、持久化任务和请求体均使用 GPT 组合。
3. 当前任务对象更新不会把新选择覆盖成旧选择。
4. 最近三轮中的有效 HTTPS、站内路径和合法图片 data URL 被保留。
5. 损坏 base64、非图片 data URL、`blob:` 和空值被过滤。
6. 历史图片全部失效时，纯文本请求仍发送且不包含 `images`。
7. 当前上传图片无效时请求不发送。
8. CanvasEditor 与 Deep Research 使用同一模型选择快照。
9. 长对话下聊天模型和图像模型菜单不被消息内容覆盖，菜单项保持可点击。

局部测试通过后依次运行：相关 Vitest、全量 Vitest、TypeScript、ESLint、生产构建和受保护基线。云端重新拉取 `main` 后，用现有 Chrome 标签页验证模型切换、普通对话、CanvasEditor、Deep Research，并记录 Console、请求结果和界面证据。

## 发布边界

- 所有代码和文档只进入 `main`。
- `origin/stable` 必须保持 `52f7c601ed150769e15d06fb435c6e360e28c9e7`。
- V5.8.8 继续作为只读 donor，不在其目录中写入文件。
- APIMart 或 PearAPI 没有可用真实模型时，供应商成功链路标记为“未验证”，不得用 Mock 冒充通过；本地协议与错误链路测试仍需全部通过。
