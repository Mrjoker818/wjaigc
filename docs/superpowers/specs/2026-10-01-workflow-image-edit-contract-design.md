# 工作流图像编辑节点的可信请求合同（2026-10-01）

## 2026-10-02：同步结果接受与发布的恢复边界（设计，尚未接入产品）

隔离真 PostgreSQL 已复现：供应商同步图片结果到达后，终态 `getPool().connect()` 失败并丢失工作进程内状态，原收费 `edit` 任务仍为 `processing`；`/api/poll-task` 没有远端 ID，也没有可按原 taskId 回读的已接受结果。数据库重试不能在进程消失后重建该结果，本机持久目录不能证明另一实例可读。选择现有共享 S3 作为**私有结果接受介质**；PostgreSQL 继续是任务、来源、积分、取消和终态的唯一权威，不引入第二套任务状态机。仅配置环境变量不等于证明 S3 可写可读；新文档工作流同步任务须在收费／供应商发送前完成实际私有对象探测，失败时拒绝准入，不把本机存储冒充跨实例恢复。

私有媒体键为 `private/workflow-edit/media/<taskId>/<index>-<sha256>.<ext>`，每张由后续工作流专用接受服务先完成真实图片解码校验和 20 MiB 字节上限检查，再交传输层做格式签名核对、条件写入及精确 HEAD/Range/对象版本/摘要回读确认；不得经 `/api/serve-upload` 对外开放。所有实际结果槽位都要接受，不得只保留首图。最后写 `private/workflow-edit/accepted/<taskId>.json`，最大 64 KiB、`If-None-Match:*`；清单冻结 taskId、actor、请求摘要、providerId/modelId、槽位及 SHA-256，不含供应商原始 URL、密钥、data URL 或图片字节。同 taskId 的重放只可读取并核对完全相同的清单；冲突不可覆盖。媒体先于清单落盘，缺清单的孤儿对象由持久清理机制收口。

清单存在仅表示**供应商结果已被安全接收**，不表示任务完成、可收费终结或可公开交付。恢复者按原 taskId 查询收费任务与冻结工作流意图，核清单身份和全部媒体字节，在任务／来源锁下复查编辑权、授权代次、源版本与精确放置、取消状态。受管输出媒体可在短事务外准备，但最终须在同一短事务写 owner 的唯一 `workflow-output` 资产版本、发布检查点和任务完成／积分终态；不得先把任务标 `completed` 再等待媒体发布。撤权先提交时应确定性拒绝并一次退款；取消、超时或失败终态不能被迟到 S3 对象复活。未知 COMMIT 只能按任务与唯一输出检查点回读，不重发供应商，不二次扣费。预备媒体失败、S3 接受失败、清单冲突、跨实例接手和清理失败都需专门测试；双存储同时故障不可宣称零丢失，只能保持待核对并暴露运维对账项。

本轮仅落地并测试 S3 私有清单／媒体传输原语：其读写不经过公开命名空间，按精确键及对象版本有界回读。**尚未**建立清单格式、供应商结果到清单的提交、收费前实际探测、终态／轮询恢复、原子发布、清理或真实多实例验证；原真库 RED 仍是当前产品状态。

## 2026-10-02：普通擦除／蒙版的文档来源终态栅栏

本地实现补记：工作流发送的 `assetSourcePlacementId` 必须在收费来源检查中选中该精确活跃放置，并进入幂等请求摘要；不能在所选放置被删除时改选同版本的另一放置。隔离真库先得到错误公开交付的 RED，修后双放置用例 GREEN。完成任务的轮询、恢复列表和同键重放核对冻结的授权代次，防止撤销再重授读取旧结果。未知 COMMIT、租约接手、真实崩溃及跨工作区资产发布仍属未验边界。

同日验证补记：最终 COMMIT 回执丢失的本地故障注入已覆盖提交前与提交后两态；提交前保持收费任务待核对，并用既有已接受检查点轮询恢复，提交后核实同一持久成功，无第二次供应商 POST 或错误退款。**未知 COMMIT 的本地模拟已验证**，真实断线与杀进程、租约接手仍未验证；上段“未知 COMMIT 未验”为此前记录，不应作为当前结论。

同日租约补证：在远端直返已接受、结果下载期间强制旧租约到期并由新工作器抢租，旧工作器不能完成或交付；新租约到期后的轮询接续同一检查点，零第二次 POST／扣费。**同进程真库租约换主已验证**；上段“租约接手未验证”是修前记录。真实杀进程、多实例重启和发布版本接缝仍未验证。

当前 `ordinary-inpaint` 已在收费事务和供应商发送阶段复核文档来源，但私有恢复输入只保存源图、蒙版与请求摘要；同步完成和 `/api/poll-task` 恢复直接调用通用 `completeCloudTask`。远端接受后若编辑授权、项目文档开关、源版本或画布 placement 被撤销，租约与任务状态 CAS 本身不能阻止迟到图片完成。

选用现有私有输入表承载同任务来源快照，而不信任客户端在轮询时再次提交的 URL，也不复用绑定工作流节点语义的 `wujie_workflow_edit_publications`。收费 `beforeCharge` 在同一事务内选定一个当前投影中活跃的源 placement，冻结项目 owner、授权代次、父版本、placement ID、规范 URL 与校验 origin；任务标记明确区分文档来源与个人来源。已存在的同键任务只按其原始身份恢复，不用新请求重写快照。缺失或损坏文档快照必须待核对／拒绝完成，不能降级为普通 `completeCloudTask`。

同步和异步完成使用同一短事务：先锁本地任务，再读取并验证私有快照，然后按冻结授权代次、父版本、**精确 placement ID**、规范 URL 锁定当前文档来源；在这些 SHARE 锁内调用带租约 owner／attempt／deadline 的 `completeCloudTask` 并提交。与撤权并发时由锁顺序决定胜者；撤权先提交则结果不得完成。已确定的撤权可由同一任务原子进入 failed/refunded，一次退款；提交回执未知不能推断为失败或盲退款，必须先查持久终态。已落地的可公开文件不等于文档发布或三工作区版本，后续仍需独立资产版本收养。个人项目保持现有受管结果和账务路径。

验证先用隔离真 PostgreSQL 和受控供应商制造“已接受后撤权／删除特定 placement／禁用项目”的同步及异步交错，断言不交付图片、唯一消费／退款、无第二次供应商 POST；再覆盖仍授权的正常完成、重复轮询、租约接手和未知 COMMIT。此设计不宣布全平台验收，Pear 专项不在范围。

## 事实与问题

- 改动前，`getNodePropertyFields('ai-edit')` 将 `edit` 设为默认动作，同时还提供 `erase/mask/extend`；`buildNodeExecutionRequest` 把四者都送到 `/api/image-edit`，`ai-color-adjust` 也发送该动作。目标路由只接受明确的十动作，故这两种节点的默认请求在图像执行前被拒。现已为两者补独立路由/字段测试，但不能据此认定完整编辑合同完成。
- `/api/edit` 是自然语言修图接口，主图字段为 `image`，不是 `imageUrl`；其异步任务由现有 `cloud_tasks`、轮询和收费逻辑管理。仅替换 URL 而不改请求体仍会得到“请先添加图片”。
- 工作流输入解析已能携带上游 `assetVersionId/assetId/placementId`，但普通 `input-image` 并不强制使用受管资产；工作流执行器也会给子请求添加 `projectId`。因此节点 JSON 中的版本 ID 或 URL 本身都不能证明文档来源。
- `/api/edit` 目前仅在文档项目且画布工作区时使用画布来源及发布准入；简单改传 `assetWorkspace='workflow'` 会跳过该路径。现有 `CanvasTaskPublicationInput`、事务准入和画布投影都硬性限定 `canvas`，不能只扩大一个 TypeScript 联合类型来冒充工作流发布。工作流父任务的持久状态不等于子编辑已收费、已发布的证明。
- `canvas-edit-route-postgres.test.ts` 的历史兼容矩阵还明确允许**直接**以文档项目和 `assetWorkspace='workflow'` 调 `/api/edit`，收费与供应商执行后 `wujie_canvas_task_publications` 仍为空。这是既有接口行为，不可误称新节点改动造成；但它也不能作为可信跨工作区发布的验收依据。迁移时须保留受权用户的功能结果，同时补齐来源与项目资产版本，而不是仅把这条兼容路径禁用。
- 通用工作流异步执行器现有的 `executeAsyncTask` 在取得子 taskId 后留在单次请求里轮询；与分层任务专用的 `activeLayerTasks` 不同，普通图像编辑子 taskId 尚未在父执行状态中作为恢复检查点持久化。改动前 `HTTP 200` 且 `success:false` 的无 taskId 响应也可能被同步分支当作成功；该失败判定已局部修正并回归，子 taskId 恢复仍待验收。
- 循环体下游原本直接 `fetch`，不经过普通节点的子任务提交/轮询入口。局部实现已将 `ai-edit` 四动作及 `ai-color-adjust` 接回同一入口，缺声明项目时在发送前拒绝；其他循环异步节点仍保持旧路径，不能借此宣称循环执行整体已具备恢复合同。
- 擦除/蒙版此前只发送 `action`，缺 `/api/image-edit` 必需的 `editMode` 和 `maskImage`；节点本身也没有 `in-mask`，因此真实画布无法建立合法蒙版连线。现已按动作添加端口与字段、无蒙版发送前拒绝，并在编辑器加载旧保存节点时补齐端口；用真实节点端口定义、连线输入和请求构建测试，但蒙版受权来源、文档发布及浏览器端到端仍未验收。
- 2026-10-01 进一步用隔离 PostgreSQL 复现：文档编辑者有有效项目授权和所有者资产版本时，原工作流输入解析仍按编辑者 `owner_id` 查询，返回 `ASSET_NOT_FOUND`。已在该输入绑定点增加窄范围所有者解析：仅该错误触发当前项目授权查询，确认是文档编辑者后按实际所有者读取规范版本 URL，并创建所有者名下的 `workflow-input` placement；撤权后新绑定被拒，客户端伪造 URL 不成为输出。此处是**输入点的局部修复**，既没有在子任务收费事务内复验，也没有发布编辑结果。
- 上游真实结果的 `assetVersionId/placementId` 原先未进入编辑子请求，无法成为后续事务准入的候选。构建器已补传完整二元组，且连线新身份优先于节点旧配置、缺 placement 不拼接旧值；这只是请求数据传递，不等于服务端相信这些字段。蒙版连线目前仍只有 URL，受权蒙版版本/安全媒体准备继续开放。
- 现有 `task-projector` 虽有 `workflow-output` placement，但它以子任务 actor 作为项目资产 owner，并直接使用任务输出 URL；不能把它当成文档编辑者结果的已验证媒体收养。`task-publication-intent/output` 与 `document-media-import` 又绑定画布选中 placement、画布命令和画布投影。`createBillableCloudTask` 提供同事务 `beforeCharge` 钩子，但工作流尚无持久的发布意图、重放身份及由受控媒体到工作流资产版本的提交路径。因此实施时须先定义并验证并列的工作流任务意图与发布检查点，不能借旧 `assetWorkspace='workflow'` 兼容入参或单一投影函数绕过画布约束。

## 方案选择

采用**按语义路由＋共用既有任务权威**。`ai-edit` 的语言修图及 `ai-color-adjust` 送 `/api/edit`，按该接口使用 `image/prompt/model/providerId`；`erase/mask/extend` 保持 `/api/image-edit`，分别按实际蒙版或扩展合同生成请求。子任务仍是唯一的收费、供应商检查点、退款和媒体结果权威；工作流父任务只引用子 taskId、状态和已发布结果，不增加第二套扣费或远端状态机。

拒绝两个替代方案：给 `/api/image-edit` 直接加 `edit` 别名会把语言修图偷偷塞进另一套模型/蒙版/费用语义；把所有节点改成 `inpaint` 会在没有蒙版时伪造操作，丢掉自然语言修图与调色原意。新的第三个编辑端点只会复制鉴权、任务和账务，也不采纳。

## 文档工作流发布接缝裁定（设计，尚未实现）

选择**子任务原子冻结工作流发布意图＋完成后受控媒体收养**。`cloud_tasks` 及现有积分流水继续是供应商状态、收费和退款的唯一权威；工作流发布记录只描述“此已收费子任务允许把哪一个输出放入哪个项目/工作流”，不另建模型任务状态机。比较过的另外两条路径均不满足合同：把 `CanvasTaskPublicationInput.workspace` 改成联合类型仍会执行画布选中快照、画布命令和投影校验；直接调用 `task-projector` 则按执行者而非项目所有者写资产，并从任务结果 URL 创建 ready 版本，缺媒体字节证明。

1. **事务准入。** 子 `/api/edit` 的文档工作流请求须带由父执行记录确定的 `executionId/nodeId/attempt` 和输入 `assetVersionId/placementId`；路由不能信任客户端自报的 owner、规范 URL 或父任务状态。在 `createBillableCloudTask` 的现有幂等锁与扣费事务内，锁当前 editor grant、文档项目、唯一活跃的 `workflow-input` placement、ready 图片版本及资产；核对 owner/project/workflow/entity/version、规范 URL、模型 pair、请求摘要，然后与子任务和扣费同 COMMIT 保存版本化工作流意图。重放分支也必须核对既存任务、意图、摘要和当前授权，不得只凭同键直接返回。`beforeCharge` 只在新任务运行，故不能仅把这些校验挂在该钩子；需在账务服务增加有类型的工作流准入/重放分支。撤权、换版、换 URL 或换模型在发送供应商前以零新增消费拒绝。
2. **持久身份。** 新工作流意图与子任务 ID 一对一，冻结 actor、项目 owner、projectId、workflowId、nodeId、grant generation、来源版本/placement、请求摘要和来源指纹；输出检查点以 `(taskId, outputIndex)` 唯一，记录实际资产版本和 placement。字段、外键和摘要须由服务端生成；JSON 节点配置只作候选，不充当授权凭证。子任务幂等身份保留 `executionId/nodeId/attempt`，未知提交先按身份查既有任务，不重新 POST；父执行记录持久引用子 taskId。
3. **完成与收养。** 供应商成功只能使原子任务进入可发布状态，不能让父节点以远端 URL 宣称共享版本。输出先经现有受限本地/S3/安全下载、长度/MIME/校验和与图片解码能力读取并持久化字节；最终短事务再次锁任务、意图、grant、项目、来源快照和输出检查点，原子写 `wujie_assets`、`wujie_asset_versions`、父版本关系及 `workflow-output` placement，owner 使用项目所有者，计费人仍是执行者。派生输出建新资产，不覆盖原资产；不写画布 projection。相同 `(taskId, outputIndex)` 必须返回同一版本，冲突摘要拒绝；COMMIT 回执未知时只读回已授权检查点，不能清理可能已发布的媒体或重扣费。
4. **可恢复交付。** 子任务已完成而媒体/发布未完成时向工作流返回 `publication-pending`，不暴露未受管结果 URL；持久恢复器只重试发布，不重复供应商调用或扣费。父节点只在检查点与资产版本相符后保存 `taskId/assetId/assetVersionId/placementId`，供画布、节点和聊天读取；取消/失败终态与迟到输出保持原有一次退款/终态屏障。首次提交取得子 taskId 立即持久化父检查点，重开只轮询已有子任务。直接以 `assetWorkspace='workflow'` 调用的旧文档请求应通过服务器对规范 URL 与唯一受权版本/placement 做无歧义迁移；无法证明来源时收费前明确拒绝，个人项目兼容路径不受此文档规则影响。

此接缝先以独立真库计划分期：原子准入/重放 → 安全媒体与唯一资产发布 → 无流量恢复及父 taskId 恢复 → `/api/image-edit` 其余动作共享同一来源/发布合同。每期只证明自身边界；当前代码与测试**均未实现上述工作流发布意图**。

## 来源、执行与结果合同

1. 纯节点构建器只负责动作到请求形状的确定性映射，不负责信任。已选 provider 与 model 保持精确 pair；空模型按目标接口明确的默认或模型选择规则处理，不发送空字符串冒充模型。旧节点 JSON 的 `action='edit'` 保持可用；未知 action 在发送前明确拒绝。工作流执行器对新接通的语言编辑/调色子请求须有已认证项目作用域；项目缺失不得把文档图片降成不受管的 unscoped 编辑。
2. 执行器以已认证 actor、项目和工作流作用域从上游真实结果解析主图/蒙版。文档项目必须在**子任务收费和供应商发送前**按当前版本、placement 和规范 URL 重新核验，不能仅转发客户端 `assetVersionId`；缺版本、跨项目、撤权、替换后的旧 URL 明确拒绝并保持零子任务消费。个人项目旧 URL 路径仍保留，但不能静默写入协作文档。蒙版要么来自受权版本，要么经过 actor/project/request 绑定的受限媒体准备；`blob:` 或裸 data URL 不能写入可恢复任务描述。
3. `/api/edit` 对工作流文档模式需建立与画布并列、但不伪装成画布投影的受权发布意图和恢复复验，输出落同一项目的资产版本并由工作流节点引用。实施前先选择具体的任务发布/媒体导入接缝；现有画布发布函数中含有画布 placement 与投影专属假设，不能直接把 `workspace` 改成联合类型。`/api/image-edit` 的三种动作沿现有十动作计划接入同样的来源、报价和终态屏障；尚未接好时文档请求应可解释地拒绝，而不是免费或伪成功。
4. 子请求使用由工作流 execution/node/尝试代次确定的幂等身份；响应丢失或重开先用此身份查询原子任务，已接受异步仅轮询，未知提交不重发。首次收到 taskId 应立即持久化父执行检查点，父任务取消后不可让迟到完成覆盖取消状态。失败/取消按子任务冻结价最多退款一次。工作流持久结果存子 taskId 和最终受管资产引用，不能用临时 HTTP URL 充当共享结果版本；原素材不覆盖。
5. `parseApiOutput` 已识别 `result.image.url` 与 `result.images[0].url`；仍需测试 `/api/edit` 直接完成、202、轮询完成及恢复后输出都导向同一最终版本。供应商原始错误、任务 ID 与失败状态对用户可见，不将 HTTP 200 中的 `success:false` 当成功。

## 验收与边界

先用真实工作流节点构建器和接口验证复现默认编辑/调色 400；接着分别以文档本人/编辑者、个人模式和双用户双项目做受控 PostgreSQL/HTTP RED→GREEN。至少覆盖正常编辑、调色、带有效蒙版擦除/蒙版、扩展、无蒙版拒绝、错误 action、伪造/跨项目/旧版来源、改价、相同与冲突幂等键、同步/异步、响应未知、撤权、取消/唯一退款、父任务恢复以及图片版本和三工作区读回。只替换外部供应商网络，不 mock 任务、项目授权、账本、版本或发布事务。独立代码复审与正确预览页 Chrome 验收分开留证；严格构建/NFT、保护基线、真实付费及云端多实例未绿时不宣称发布通过。
