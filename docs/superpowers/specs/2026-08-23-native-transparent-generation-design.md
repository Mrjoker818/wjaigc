# 原生透明 PNG 生图能力设计

## 目标

让无界中所有图像生成入口共享同一套透明背景能力。支持该能力的模型可请求原生透明 PNG；不支持、拒绝参数或返回伪透明结果时，不静默调用二次去背景模型，不产生隐藏扣费。

## 范围

本轮包含：

- 主图像生成面板、快速创作、参考图组、融图组、图片工具栏图生图、底部图像生成器。
- 节点模式中的图像生成类节点。
- 无限画布 AI 对话、独立智能对话和 Agent 的 `generate_image` 工具。
- 品牌、Logo、包装、展陈、贴纸等复用 `/api/generate` 的业务入口。
- 模型能力识别、请求归一化、透明结果校验、错误提示、持久化与下载契约。

本轮不包含：

- 自动调用 remove.bg、Pear 或其他去背景服务作为透明生成兜底。
- 重构现有元素分层、Pear PSD 分层或本地分层引擎。
- 对不支持透明背景的模型伪造支持能力。

## 用户体验

### 背景模式

统一提供三种模式：

- `auto`：由模型决定，保持现有行为。
- `transparent`：请求真正透明的 PNG。
- `opaque`：明确请求不透明背景。

透明模式只能与 PNG 或 WebP 搭配；本轮 UI 自动锁定 PNG，避免供应商兼容差异。模型不支持 `background` 时禁用透明选项，并说明原因。

### 全入口一致性

- 通用生成入口显示统一的“背景”控件。
- 选择结果随当前图像模型保存，其他画布生图入口读取同一偏好。
- 业务面板在生成按钮附近显示当前输出状态，如“透明 PNG”，避免隐藏状态。
- 节点模式在图像生成节点上提供背景字段，并将其写入工作流请求。
- 聊天或 Agent 在用户明确说“透明背景、无背景、透明 PNG”等语义时传递 `transparent`；未明确要求时使用 `auto`。

## 统一数据契约

客户端领域类型：

```ts
export type ImageBackgroundMode = 'auto' | 'transparent' | 'opaque';
export type ImageOutputFormat = 'png' | 'jpeg' | 'webp';

export interface ImageOutputPreference {
  background: ImageBackgroundMode;
  outputFormat: ImageOutputFormat;
}
```

向 `/api/generate` 发送时统一转换为：

```json
{
  "background": "transparent",
  "output_format": "png"
}
```

接口同时兼容历史 camelCase 输入，但内部只使用规范化后的 snake_case 字段。显式请求优先于已保存偏好；没有显式值时使用 `auto`。

## 能力与兼容

- `getModelCapabilities(modelId).supportsBackground` 是前后端共同的能力来源。
- `transparent` 请求只对支持背景参数的模型保留。
- 透明模式强制 `output_format = png`。
- 不支持的模型收到透明请求时返回明确的可操作错误，不静默改成白底，也不切换供应商。
- 管理员配置的兼容供应商仍以模型 ID 能力为基础；后续可增加供应商级覆盖，但本轮不引入新的数据库字段。

## 透明真实性验证

生成结果落库或进入画布前，记录透明度验证结果：

- `verified`：存在 Alpha 通道且至少一个像素的 Alpha 小于 255。
- `opaque`：格式可解码，但所有像素完全不透明。
- `unverified`：远程文件暂不可下载或格式不可检测。
- `invalid`：文件损坏或 MIME/格式不一致。

透明请求得到 `opaque` 或 `invalid` 时任务不得伪装为“透明 PNG 成功”。保留原始结果，向用户显示“模型未返回真实透明背景”，并提供显式“一键去背景”操作。该操作是新任务，必须再次确认并单独计费。

棋盘格是像素内容而非透明度。验证只依据解码后的 Alpha 通道，不依据文件扩展名、MIME 或视觉外观。

## 失败与计费规则

- 不因透明验证失败自动创建第二个任务。
- 不自动切换模型或供应商。
- 原始生成任务是否计费遵循现有供应商任务终态；透明验证不重复扣费。
- 用户主动选择“一键去背景”时创建独立幂等任务并展示费用。
- 错误信息区分参数不支持、供应商拒绝、结果不透明和结果无法验证。

## 回归边界

- `auto` 模式必须与改造前请求行为一致。
- 多图 `n > 1` 每张结果独立验证 Alpha，不等待所有图片才统一展示。
- 参考图、融图和图生图不得丢失 `image` / `image_urls`。
- 保存、刷新恢复和下载后仍保留原始 PNG Alpha。
- 不支持透明背景的模型不得收到 `background` 参数。
- 所有直接调用 `/api/generate` 的入口必须通过统一请求构建器或由服务端规范化。

## 非专用分层技术路线（后续独立阶段）

无专用分层模型的产品通常组合主体分割、OCR、连通区域、深度估计、Alpha 蒙版、背景修复和矢量描摹，再用重建误差验证结果。无界现有本地管线已具备 RGBA 图层、区域提取、边缘去白、偏移保存和重建质量门禁，可在后续阶段增加：

1. OCR 文字层与文本元数据。
2. 通用主体/实例分割提升语义边界。
3. 单目深度用于图层前后排序。
4. 可选背景补全，明确标记 AI 推测内容。
5. 重建误差与人工蒙版修正闭环。

从单张扁平图片无法完美恢复原始作者图层。产品必须区分“可见像素分层”“AI 补全分层”和“原始工程图层”，避免误导用户。
