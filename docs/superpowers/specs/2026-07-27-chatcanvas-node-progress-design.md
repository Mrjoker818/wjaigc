# ChatCanvas 节点批注与进度显示增量设计

## 目标

在不改变现有 ChatCanvas 融合批注入口和执行协议的前提下：

1. 修复节点模式中框选、画笔和箭头无法完成拖拽的问题。
2. 节点模式优先继承当前有效的批注模型，避免每次打开都回到模型列表第一项。
3. 在无限画布和节点模式共用的批注输入栏中显示任务阶段、百分比和已用时间。
4. 保持取消、失败和完成状态与后端任务终态一致。

## 已确认根因

- 节点批注工作区中的 `NextImage` 保留浏览器原生拖拽和指针命中，导致外层工作区无法稳定收到完整的 Pointer 手势。
- 节点批注模型状态直接使用 `models[0]` 初始化，并在模型数组变化时重置。
- 批注客户端已经能读取任务 `progress`，但无限画布没有保存或传递该值，`AnnotationComposer` 也没有进度展示接口。
- 同步型供应商调用在长时间等待期间缺少中间任务更新，因此只能从 `0` 直接跳到 `100`。

## 方案

### 节点手势

节点工作区图片仅作为视觉内容，不作为交互目标：

- 设置 `draggable={false}`。
- 增加 `pointer-events-none` 与 `select-none`。
- 阻止原生 `dragstart`。
- 所有批注手势继续由工作区根节点统一接收和 Pointer Capture。

### 模型继承

为 `NodeAnnotationWorkspace` 增加可选的 `preferredModelId`：

1. 编辑已有批注节点时优先使用该节点保存的 `providerId::modelId`。
2. 新建节点时优先使用父级传入的当前批注模型。
3. 仅在首选模型不存在时选择当前模型列表第一项。
4. 模型列表刷新时，如果当前值仍有效，不得重置。

不按供应商名称硬编码排除 FHL 或虚宝；可用性应由模型配置、健康状态或用户选择决定。

### 混合阶段进度

进度由真实后端阶段驱动，前端只在同一阶段内做受限平滑：

| 阶段 | 服务端进度 | 前端显示 |
| --- | ---: | --- |
| 校验批注 | 5 | 正在校验批注 |
| 准备素材 | 15 | 正在准备图片和蒙版 |
| 提交模型 | 30 | 正在提交模型 |
| 模型处理 | 45 | 模型正在处理 |
| 保存结果 | 90 | 正在保存结果 |
| 完成 | 100 | 修改完成 |

前端平滑进度不得超过当前阶段的上限，也不得超过 `95%`。只有服务端返回终态 `completed` 后才能显示 `100%`。失败、取消和超时不得继续增长。

`AnnotationComposer` 新增：

- `executionProgress?: number`
- `executionStage?: string`
- `executionStartedAt?: number`

执行时显示进度条、百分比、阶段文本、已用时间和取消按钮。未执行时保持现有操作栏布局。

## 错误与终态

- 取消时立即停止前端平滑进度，并调用现有取消接口。
- 失败时保留后端错误信息，不伪造 `100%`。
- 组件卸载时清理计时器和 AbortController。
- 重复点击仍由 `annotationTaskId` 和 `isExecuting` 双重阻止。

## 测试

1. E2E 在节点批注工作区真实拖出框选和画笔，断言产生对应 SVG 批注。
2. 组件测试验证节点图片不再接管指针或原生拖拽。
3. 单元测试验证首选模型存在时被保留，模型数组刷新不重置。
4. 组件测试验证执行时显示阶段、百分比、进度条、已用时间和取消按钮。
5. 客户端测试验证进度单调、不超过 `95%`，完成后才到 `100%`。
6. 回归无限画布批注创建、执行、取消、保存和刷新恢复。

## 非目标

- 不重构整个批注执行器。
- 不修改供应商计费、幂等或授权协议。
- 不把估算进度冒充供应商原生进度。
- 不调整 ChatCanvas 入口位置或既有视觉主题。
