# 短剧工作台升级设计

用户已在仓库对照分析后明确要求“根据分析进行升级”，并已授权范围内自主实施，不重复请求常规确认。本设计据该批准落地。

## 目标与边界

基线 `83a19b79e9c42d9a58bd15b9a25490a3abd22313`。独立实现已批准的剧本贯通、版本联动、制作恢复和交付增强；仅借鉴火宝的产品流程，不复制其代码、提示词或素材。复用现有用户、产品权限、资产、任务和积分保护。不操作业务数据库、不运行既有删除性迁移、不修改 stable、不强推。开发提交在 `codex/drama-upgrade-20261120`，发布与 Coze 同步必须串行通过原发布检查。

## 已有剧本流程

入口明确区分“已有剧本”与现有“从创意生成”“小说改编”“制作包恢复”。支持粘贴、UTF-8 TXT、DOCX；复用既有 mammoth/JSZip，文件须先做压缩体积、条目和解压体积限制。导入先解析预览，再使用现有项目创建 API 保存，不在解析阶段创建业务项目或调用生成模型。

解析保留输入原文，提取显式的分集、分场、角色和台词。缺少结构或有歧义时明确警告，不伪造外貌、剧情或道具。支持随后用已授权对话模型辅助识别结构，模型只能给出原文位置与实体候选，正文与台词从原文截取。原稿与小说改编语义不同。

新增可选字段向后兼容：`doc.sourceScript = { originalText, fileName?, format: 'text'|'txt'|'docx', importedAt }`；`episode.structuredScript` 保存解析时的正文快照；`scene.sourceRange = { start, end }` 为该集正文的 UTF-16 半开区间。旧项目不要求这些字段。文档校验须保留并验证这些元数据及引用完整性。

正文编辑后与已解析快照不一致时显示重新解析提示。分镜使用当前场对应原文，旧项目仍可使用既有分场内容。重新解析优先按原场次匹配保留 ID、镜头和已产出素材，清楚标记变更范围，不静默覆盖成品。

## 制作与版本

角色、场景、道具继续使用现有 ID、锁定图和历史版本。新增别名与造型状态时必须可审核，不按同名盲目合并。分镜规划绑定明确的已授权供应商/模型，并按视频模型能力及台词长度安排时长。

生成记录保存输入版本；修改关联正文、画面、台词、音色或素材时标记受影响产物过期，保留历史，并阻止旧产物被当成当前成片。报价需比较完整输入配置，包含模型、参数、时长和素材版本，而非只比较项目 ID 集合。

制作计划分阶段保存，复用现有持久化任务框架。单项回执与整个运行计划分开恢复；未知提交结果先查原操作，不自动重发付费生成。供应商成功、结果回读、入库、可合成分别记录；交付失败只恢复交付。

## 交付与验收

保持现有视频、字幕、音乐和剪辑能力，增强输入过期提示、审片导航和整项目制作包。归档明确“选用素材/含历史”模式，引用与文件清单可校验。

验收覆盖原文及台词不被静默改写、结构解析与引用正确、正文修改影响追踪、旧项目兼容、模型精确授权、保存冲突、取消及原任务恢复、报价过期、跨集素材和离线包完整性。先隔离合成测试和构建，再独立预览真实 UI；不将假模型通过当成真实供应商通过。
