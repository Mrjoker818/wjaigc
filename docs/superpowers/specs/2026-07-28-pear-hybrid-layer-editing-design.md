# Pear 混合分层与“编辑元素”融合设计

## 1. 目标

将管理员已配置的 Pear `Image-Layered` 模型接入图片浮动工具栏的“编辑元素”，并提升本地分层质量。默认采用 Pear 语义分层加本地质量精修；Pear 不可用时使用增强后的本地分层兜底。

成功标准：

- 点击“编辑元素”后可以直接处理当前选中图片，不要求用户输入 URL。
- Pear 返回的 PSD 被解析为真实可编辑图层，而不是被当作普通图片。
- 图层保留名称、层级、位置、透明度、混合模式和画布尺寸。
- 分层结果可以在现有 PSD 分层编辑器中移动、隐藏、锁定、重命名、排序和导出。
- 智能模式下 Pear 失败可以自动回退到本地；云端模式失败时不静默降级。
- 同一次操作最多创建一个有效云端任务并扣费一次，失败退款只执行一次。
- 本地增强不引入 GPU 强依赖。

## 2. 当前状态与问题

管理员配置：

- 提供商：Pear
- Base URL：`https://api.pearapi.ai`
- 类型：`layer`
- 模型：`Image-Layered`

Pear 官方协议：

- 主提交：`POST /v1/images/edits`
- 兼容提交：`POST /v1/images/generations`
- 异步查询：`GET /v1/images/tasks/{id}`
- 主要输入：`model: image-layered` 和一张 `image`
- 输出：同步结果 URL 或异步任务 ID；最终产物是分层 PSD 文件。

当前“编辑元素”已经打开 `PsdLayerEditor`，但后端存在三项协议错位：

1. `/api/segment-elements` 优先调用 `/chat/completions` 和 `/segment`，不符合 Pear Image-Layered 协议。
2. `/api/layered-decompose` 虽调用 `/images/edits`，但把返回 URL 当作普通图片图层，没有解析 PSD。
3. 本地兜底主要依赖 RGB 颜色差和连通域，缺少边缘、透明度与重建质量检查，复杂图片质量低。

## 3. 方案选择

采用“Pear 主分层 + 本地精修 + 增强本地兜底”。

不采用并行双引擎后合并，原因是并行结果缺少稳定的图层对应关系，容易产生重复图层、错位、残影和重复费用。

三种用户模式：

- `smart`：默认。Pear 分层成功后执行本地精修；云端失败后使用增强本地分层。
- `cloud`：仅使用 Pear；失败直接显示原因并结算退款。
- `local`：仅使用增强本地分层，不调用 Pear、不产生云端模型费用。

## 4. 总体架构

`/api/layered-decompose` 作为“编辑元素”和 PSD 导出的统一分层入口。`/api/segment-elements` 与节点模式通过共享服务调用相同的 Pear 适配器和本地管线，不再各自实现不同协议。

新增或整理以下边界：

1. `PearLayeredAdapter`
   - 解析管理员提供商和授权模型。
   - 提交、轮询、取消 Pear 任务。
   - 识别同步与异步响应。
   - 返回统一的 PSD 产物描述，不直接生成 UI 图层。

2. `PsdLayerExtractor`
   - 安全下载 PSD。
   - 使用项目已有 `ag-psd` 解析图层树。
   - 将像素图层转换为透明 RGBA PNG。
   - 保留层级、偏移、透明度、混合模式、可见性和名称。

3. `LayerPostProcessor`
   - 清理边缘色污染、透明孔洞、小碎片和重复图层。
   - 规范化每层画布与偏移。
   - 生成缩略图和编辑器需要的元数据。

4. `LocalLayerPipeline`
   - 在无 Pear 结果时执行增强本地分层。
   - 不声称达到云端语义模型同等质量。

5. `LayerQualityGate`
   - 验证图层有效性和重建一致性。
   - 决定接受、带警告接受或回退。

## 5. Pear 调用协议

### 5.1 提交顺序

对当前选中图片优先调用：

```http
POST /v1/images/edits
Authorization: Bearer <provider key>
Content-Type: application/json

{
  "model": "image-layered",
  "image": "<public URL, data URL or validated base64>",
  "task_type": "async",
  "response_format": "url"
}
```

`/v1/images/generations`仅作为协议兼容回退。仅当主接口在创建任务前明确返回 404、405 或可识别的“不支持端点”错误时尝试；已经得到任务 ID 后禁止切换端点。

### 5.2 轮询与终态

- `queued`、`running`：继续轮询并更新进度。
- `completed`：提取 `output.data[].url`、`output.image_urls[]` 或兼容字段中的 PSD URL。
- `failed`：记录上游错误并进入失败结算。
- `cancelled`、`timeout`：主动终止轮询，不允许后来覆盖为完成。

使用数据库任务记录保存 `userId`、`providerId`、`modelId`、上游任务 ID、端点、状态和扣费状态。客户端刷新后可以恢复任务。

### 5.3 幂等与扣费

- 客户端为一次“编辑元素”生成幂等键。
- 唯一性至少绑定 `userId + idempotencyKey` 和规范化请求摘要。
- 主端点与兼容端点属于同一业务任务，不分别扣费。
- 只有任务创建成功后进入已扣费状态。
- `failed`、`timeout`、`cancelled`使用数据库条件式终态结算并最多退款一次。

## 6. PSD 安全解析

PSD 下载必须通过统一安全下载器：

- 只允许 HTTP/HTTPS。
- DNS 解析后拒绝私网、环回、链路本地和保留地址。
- 禁止重定向到未验证地址。
- 限制响应体积、下载时间和并发数。
- 校验 PSD 文件签名，不以 URL 后缀或响应 MIME 作为唯一依据。
- 设置 PSD 尺寸、图层数、总解码像素和嵌套深度上限。

解析规则：

- 保留可见像素图层与组结构。
- 调整图层、智能对象和不支持的效果按需栅格化，但保留原始名称和来源说明。
- 空图层不进入编辑器，但记录在诊断信息中。
- 每个输出 PNG 使用安全生成的服务端文件名并持久化。
- 不在日志中记录图片内容、API Key 或完整远程 URL 查询参数。

## 7. 本地质量增强

### 7.1 Pear 结果精修

本地处理不重新决定 Pear 的语义分层，只修复图层质量：

- 透明边缘去白边、黑边和前景色污染。
- 小孔洞填充和孤立噪点移除。
- 轻量形态学闭运算与 0.5 至 1.5 像素边缘羽化。
- 保留半透明阴影、玻璃和柔光区域。
- 去除完全重复或近乎空白图层。
- 统一画布尺寸，同时保留原始图层偏移。

### 7.2 增强本地兜底

替换单纯 RGB 连通域为分阶段 CPU 管线：

1. 自动方向、色彩空间和 Alpha 规范化。
2. 优先使用当前可用的本地去背景能力生成主体 Alpha；不可用时继续纯 CPU 路径。
3. 使用 Lab 色差、亮度梯度和边缘强度构建候选区域。
4. 进行边缘约束区域生长，而不是逐像素固定 RGB 阈值。
5. 合并过度切碎区域，清理小区域、孔洞和细碎边缘。
6. 生成背景、主体、阴影/装饰等有限层级，并明确标记为本地推断。

本地兜底不伪造文字、人物或产品语义名称；无法可靠判断时使用“主体”“背景”“元素 N”等中性名称。

## 8. 质量门禁

每次分层至少检查：

- 画布宽高有效且与源图比例一致。
- 有效图层数在允许范围内。
- 每层 Alpha 覆盖率、像素面积和边界框有效。
- 不存在大量完全重复图层。
- 图层重新合成后与源图的归一化像素差在允许范围内。
- 透明区域、边缘污染和总解码像素没有超过安全阈值。

结果等级：

- `pass`：直接打开编辑器。
- `warning`：允许编辑，但显示具体质量警告。
- `fail`：智能模式进入本地兜底；云端模式显示失败并退款。

质量门禁不得通过捕获并忽略异常来制造成功结果。

## 9. 前端体验

“编辑元素”继续使用现有图片浮动工具栏入口。点击后显示引擎选择或沿用最近一次选择：

- 智能：Pear + 本地精修，失败本地兜底。
- 云端：Pear + 本地精修，不降级。
- 本地：增强本地分层。

进度阶段：

1. 正在读取图片
2. 正在提交 Pear 分层任务
3. Pear 正在生成 PSD
4. 正在下载并解析 PSD
5. 正在清理透明边缘
6. 正在检查分层质量
7. 正在打开图层编辑器

失败信息必须区分：提供商未配置、模型未授权、图片不可访问、上游拒绝、任务超时、PSD 无效、质量门禁失败和本地兜底失败。

## 10. 编辑器数据契约

统一图层对象至少包含：

```ts
interface EditableLayerAsset {
  id: string;
  parentId?: string;
  name: string;
  role: 'background' | 'subject' | 'text' | 'decoration' | 'shadow' | 'unknown';
  imageUrl: string;
  width: number;
  height: number;
  offsetX: number;
  offsetY: number;
  opacity: number;
  blendMode: string;
  visible: boolean;
  source: 'pear-psd' | 'local-enhanced';
  qualityWarnings?: string[];
}
```

现有 `PsdLayerEditor` 将该契约转换为 `DesignLayer`。节点模式、PSD 导出和图片工具栏共用同一转换器，避免三条链路出现不同图层语义。

## 11. 测试策略

### 单元测试

- Pear 同步和异步响应解析。
- edits 主端点与 generations 兼容回退条件。
- 已创建任务后禁止再次提交。
- PSD 图层树、偏移、透明度、混合模式解析。
- 空图层、重复图层、像素炸弹和损坏 PSD 拒绝。
- 本地边缘精修和质量评分。

### API 测试

- 未登录、无权限、积分不足。
- 提供商或模型未配置。
- Pear 401、402、404、422、429、500、超时和非 JSON 响应。
- 任务完成、失败、取消、超时和刷新恢复。
- 并发重复请求只创建一个任务并扣费一次。
- 失败退款只执行一次。

### 浏览器测试

- 从图片浮动工具栏打开“编辑元素”。
- 智能、云端和本地三种模式。
- 进度状态连续更新且无永久加载。
- Pear 图层可以选择、移动、隐藏、锁定、重命名和排序。
- 导出 PSD 后重新打开，图层位置与合成效果一致。
- Pear 失败后智能模式进入本地兜底并显示原因。

真实 Pear 调用必须使用授权账号和真实图片，并保留网络日志、服务端 requestId、taskId、截图和 Trace。没有真实 Key 时必须标记为未验证。

## 12. 发布与回滚

先通过功能开关启用 Pear 混合分层，仅对管理员测试账号开放。记录成功率、平均耗时、PSD 解析失败率、质量门禁失败率和退款一致性。

回滚只需关闭混合分层开关，恢复现有本地编辑器入口；不删除 Pear 提供商配置和历史任务。旧项目中的已有图层数据保持兼容。
