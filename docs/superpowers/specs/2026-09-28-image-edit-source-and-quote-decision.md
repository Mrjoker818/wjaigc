# `/api/image-edit` 来源与费用裁定（2026-09-28）

状态：设计裁定；302 放大与可选画质增强有未批准的本地局部实现，**完整十动作与发布验收尚未完成**。本文件补充[完整链路设计](2026-09-28-image-edit-durable-integration-design.md)，不把已完成的 j4a–j4g 组件视为十动作执行器。Pear 分层验证不在本目标；PSD 核心与未来其他 PSD 输出方案不因本裁定改变。

## 现状证据

- `image-edit/route.ts` 调用 `authorizeGenerationProject` 后丢弃返回的 `GenerationProjectAccess`；`assetParentVersionIds`、`imageUrl` 和 `maskImage` 仍可由客户端各自填写，项目身份不能证明媒体来源。准入与图像读取之间也没有同一来源版本的复验。
- 无限画布有七处直接调用 `/api/image-edit`（包括拼板后串联去背景），当前请求未传项目/来源版本；组件虽有 `projectId` 和可选 `assetVersionId`，旧图未必有后者。贴纸助手另有直接调用，放大兼容路由、工作流、Agent、聊天工具、人工修复和 Photoshop 代理也可间接触达；不能直接在服务器强制全体旧请求带版本而破坏旧画布。
- `canvas-edit-admission.ts` 已提供另一入口的文档项目意图解析、受权版本 URL 比对与重放复验，可提取或复用其规则；它不是本路由已接线的证明。`generation-project-access.ts` 明确项目准入只是一时点许可。
- 旧路由在实际候选模型接受前，以请求的模型/提供商执行一次 `calculateConfiguredCreditCost` 或 `consumeCredits`；管理员可有精确 `provider::model` 价格。自动候选 A/B 实际价格不同，现有扣费不是按最终接受模型结算。相关证据另见 SDD `task-8cb-source-billing-evidence.md`。
- `image/upscale/route.ts` 先执行 `consumeCredits('image_upscale')`，AI 分支随后 POST `/api/image-edit`，源码未转发原请求鉴权；`image/upscale-pro/route.ts` 的 AI 回退若收到异步 taskId 则返回 null。隔离真 POST 已分别证明旧 `image/upscale` 路径先扣8、子401、再退8，旧 `/api/upscayl` 外层认证成功但子401且零扣费；`upscale-pro` 用受控已接受子响应证明 taskId 被外层丢弃并返回502，但尚未证明真实任务已持久创建。其他正常成功、重复请求、异步孤儿和真实供应商账务仍须真 POST+账本验证；三条兼容路由不可在迁移中漏掉。
- 隔离真 POST+PostgreSQL 已证明 `/api/image/upscale` AI 分支先扣 8、子路由缺身份返回 401；旧 `refundCredits` 参数化多语句导致退款失败，仅留消费，原始 RED 见 SDD `task-image-upscale-bridge-preflight-20260928.md`。退款 CTE 候选在局部真库两案通过且独立只读审查认为技术上可接受，但保护许可未通过；桥接仍 401，既有重复退款、失败状态误报和扣费记账非原子缺口另需关闭。`/api/image-edit` 当前用 `requireApiAuthOrReject` 认证，却以仅解析浏览器 Cookie 的 `getSessionUser` 决定是否收费，因此补内部签名头并不等于有正确的本人收费证明。

## 兼容放大入口：单一任务与收费权威

比较三种接法：转发 Cookie 且删除外层扣费只覆盖浏览器会话，桌面令牌/可信内部调用仍可能免费；外层先扣、内层用签名头免费则没有父预付的持久证明，401、响应丢失和异步任务会再次出现账务裂缝。选择把 `/api/image/upscale`、`/api/upscayl` 与 `upscale-pro` 的 AI 回退接入**同一个图像编辑准入/执行服务**，别再用 localhost 自调用作为收费边界。适配器只归一化旧请求和响应；服务从已认证 actor 决定项目/来源、模型计划、冻结报价、幂等任务、单次消费/可信父预付及结果，不能从客户端或外层传入“已付”布尔量。同步结果和异步 taskId 均属于该任务，失败/取消只走其原子终态；兼容入口不得在子任务仍运行时把它当作失败并发起另一策略或退款。

本改造必须保留三个旧入口的可用返回合同及旧 CPU 放大语义，不能为了早绿测试删去 AI 回退。`upscale-pro` 的链式两步应明确是同一报价内的两个受控阶段，或是可见的两个独立任务/报价；不能让一个正在运行的异步阶段被同步函数返回 null 后遗弃。迁移前的旧路径按现状记录为未通过，不用临时内部免费授权伪称修复。验证要分别覆盖 Cookie、桌面令牌、可信父任务及无凭证拒绝；真实 PG 核 actor、一次收费、退款一次、幂等重放、异步恢复和结果版本，供应商 HTTP 仅替换外部网络。

### `upscale-pro` 二次精修的同任务合同（2026-09-28 实测补充）

隔离 PostgreSQL 的真实入口 RED 已证明：302 放大以 7 积分和第一张图片完成任务后，`upscale-pro` 又独立发送一次画质精修；HTTP 返回的是精修图，但任务结果仍是第一张、账本仍为 -7，而配置中精修模型另标 4 积分。该故障不是响应字段问题：任务在第二次供应商 POST 之前已终结，现有精修调用既无任务阶段检查点，也无冻结报价。原始用例为 `tests/integration/image-edit-document-source-postgres.test.ts` 的 `records the enhanced final image and both provider costs under one completed upscale-pro task`；目前为预期 RED，不得报此链路通过。

采用同一持久任务内的复合服务报价与顺序阶段，而非完成后补写结果/积分，亦非悄悄取消二次精修以换取绿色测试。准入时冻结放大和可执行精修两组精确 `providerId/modelId`、报价组成及总额；已明确指定的精修 pair 不得隐式换供应商，缺配置应在收费和放大提交前拒绝。未明确指定精修时，在收费前解析可用的默认精修 pair；若无可用 pair，明确记录“仅放大”报价与输出，不作未计费远端调用。`skipAiEnhance` 也必须进入请求摘要并得到“仅放大”报价。同键重放优先复用原任务及原报价，不能因当前配置变化再发一次精修或重收费。交互提交仍受上文报价预览/配置摘要门禁约束，不能仅在服务器暗加 4 积分。

302 输出经受控媒体保存后只是中间结果。第一阶段 accepted 不得使任务 completed；第二阶段在同一 `cloud_tasks.result.imageEditExecution` 中先写 started，再真正发送精修 POST，合法 directUrl/taskId 写 accepted。成功后持久化精修图、复验来源与发布权限，把最终图、两个实际 pair、阶段结果及总报价一次写入任务终态；同步响应、poll 和同键重放都必须读同一最终图。精修明确拒绝而无法交付所报价的完整服务时，任务按单一失败终态退还原报价；未知提交或已接受但保存/轮询故障保留待核对任务和阶段事实，不重发、不提前退款、不把未精修的中间图伪装成已完成服务。取消与迟到响应使用原任务终态屏障。受控 `enhanceViaAI` 的已有执行边界可复用，但正式调用者必须传同任务 phase、冻结 provider 和取消信号；旧无边界调用不满足本合同。

本补充只定义 302→精修路径的必要纵切，不给本地 ONNX→精修、两步链式放大、其他动作或三工作区签发完成许可。它们仍需相同的单任务/明确多任务报价、恢复与结果身份设计。验证至少覆盖 7+4→一次 -11、最终 URL 与任务/poll/重放一致、显式与默认 provider、缺模型/配置变动、同步/异步、明确拒绝、unknown、已接受后保存失败、取消、撤权和余额不足；真实账本/任务/授权不可 mock，仅替换声明的外部 HTTP。

## 裁定一：文档项目媒体必须有服务端来源证明

文档项目请求在任何收费或供应商提交前，必须将主图绑定到当前仍可访问的精确 `sourceVersionId`；修订/替换还要核对目标 placement 与当前版本。服务端从授权上下文解析规范媒体 URL，客户端传来的 URL 只用于一致性检查，不作为另一份权威。`assetParentVersionIds` 不得自证来源；按动作的其他参考图也须逐个绑定有序版本。蒙版若来自现有资产，同样绑定版本；临时笔刷蒙版须先成为服务端持久、受限、绑定 actor/project/request 的媒体，不能把一次性 `blob:`、未经验证的外部 URL 或任意 data URL 写入可恢复 descriptor。

准入后保存来源版本、规范媒体身份、授权/投影意图和摘要；每次媒体读取、远端发送以及最终发布前复验当前授权、媒体版本与相关文档状态。撤权或来源变化只能使任务安全暂停/失败，不能继续使用旧许可写文档。完整任务仍沿已有 `cloud_tasks`、租约与发布服务，不另建图片队列或资产权威。

无 `projectId` 的旧请求只能继续其个人/未限定旧结果路径，不能因在浏览器里展示而获得文档写权限；personal 项目也必须校验归属。迁移七处画布调用及工作流、聊天、贴纸、Agent、Photoshop 等消费者时，先盘点其媒体产生方式；已有资产版本直接传递，旧图片通过明确的受权导入/暂存流程取得版本。缺版本时给出可恢复的迁移错误或沿非文档个人路径，不允许把错误的项目写入静默降级为“已发布”。拼板串联去背景应使用前一步已接受、已持久化的输出身份，不以公开 URL 伪造源版本。

## 裁定二：一次冻结服务报价，不做暗中重定价

本阶段采用**一次冻结服务报价**：准入时规范化 action、`creditOp`、请求模型/提供商和当前管理员价格配置，形成任务级 `quoteAmount` 与 `quoteBasis`。显式模型按精确 pair 报价；自动模型沿现有产品语义按请求模型/模型级规则形成单一报价。交互入口须先从服务端取得报价与配置摘要并向用户展示，随后提交同一报价身份；若提交时配置已变，先拒绝并刷新报价，不在用户未知情时换价扣费。自动模式明确提示“可能使用不同实际模型，价格以本次确认的服务报价为准”。内部父已预付入口不要求二次点击，但证明必须绑定父已付额度与操作。实际接受的每个 `providerId/modelId` 单独记录在受保护执行检查点，不回填为收费依据，也不把报价说成“实际模型价”。配置后来变化不改变已创建的同键任务报价；重放不再扣；失败/取消只由同一终态按原报价处理一次退款。父已预付子任务的报价为零且必须有既有可信父证明，不能因客户端标志跳过收费。

代价：自动候选的实际模型成本可能高于或低于报价，差额由平台承担或获得，不向已提交任务追加扣费；这与“按最终模型计价”是不同产品合同。若日后要转成按最终模型价结算，必须另立余额预留、未知提交与最终结算方案，并做产品价格告知；不得在本轮用最高价暗预扣、先退后重扣或历史账本改写替代。配置免费仍必须留可审计的报价依据。客户端展示与服务端收费必须来自同一冻结报价，不能以 UI 自行推算作验收。

## 实施及验收边界

按[实施计划](../plans/2026-09-28-image-edit-source-and-quote-integration.md)先建立真实 POST+隔离 PostgreSQL 的业务 RED，再小步接线。首个纵切证明“文档项目授权版本 → 请求 → 冻结报价/任务 → 精确结果身份”中的前半段，不把它称为十动作完成；随后覆盖十动作、所有入口、父预付、供应商同步/异步/unknown、CPU 后处理恢复、poll/取消/发布及三工作区 UI。既有 protected 七文件不修改；不提交、推送、Coze、真实付费、安装或访问业务数据库。发布/完整目标只有全链路和独立验收后才能声明完成。
