# PSD 分层提交注册与取消竞态设计

## 目标

修复 PSD 分层编辑器在服务端任务尚未返回 `taskId` 时点击“取消”或“关闭”产生的孤儿任务风险。无论取消发生在提交前、提交响应途中、任务已注册后或响应不确定阶段，客户端都必须围绕同一个幂等键收敛到一个服务端任务，并在拿到任务标识后只发送一次取消请求。

## 当前根因

`PsdLayerEditor` 开始分层后立即展示取消按钮，但当前实现会先中止创建任务所用的 `AbortController`，再读取 `taskIdRef`。如果用户在 POST 已到达服务端、但响应尚未返回浏览器的窗口期点击取消：

1. `taskIdRef` 仍为空；
2. POST 响应被客户端主动中止；
3. DELETE 无法发送；
4. 服务端任务可能继续调用 Pear、扣费并生成结果；
5. 前端已回到选择页，用户无法再找到或取消该任务。

关闭窗口使用同一错误顺序，因此风险相同。

## 方案 C

### 1. 稳定操作标识

每次用户明确点击“开始分层”时生成一个 8-128 字符的幂等键，并在本次尝试、响应不确定恢复和取消确认中持续复用。只有用户在上一次尝试已经明确终结后再次主动开始，才生成新键。

### 2. 取消意图先于任务标识

取消发生时只登记意图，不中止尚未返回 `taskId` 的初始 POST。编辑器进入 `cancelling` 状态，并禁止重复开始或重复取消。

当 `onTaskId` 随后收到任务标识时：

1. 保存 `taskId`；
2. 若存在取消意图，调用一次 `DELETE /api/layered-decompose?taskId=...`；
3. DELETE 成功后中止后续轮询；
4. 普通取消回到引擎选择页；关闭意图则在取消确认后调用 `onClose`。

### 3. 重复点击去重

同一任务的取消 Promise 必须缓存。按钮重复点击、遮罩点击和标题栏关闭不得产生第二个 DELETE。取消失败时保留 `taskId`、幂等键和取消意图，重试动作仍针对原任务。

取消接口的 HTTP 成功不等于业务取消成功。客户端必须检查响应中的任务终态：只有 `status=cancelled` 才完成取消；`completed/failed/timeout` 说明终态竞争已经结束，界面显示准确终态且不再提供无意义的取消重试；`pending/processing` 仍按“取消未确认”处理。

### 4. 响应不确定恢复

若初始提交在返回 `taskId` 前出现网络中断、5xx 或无效上游响应，客户端不能假定任务没有创建。界面显示“无法确认任务状态，请重试取消”，重试时使用原幂等键再次提交同一规范化请求：

- 原任务已创建：数据库幂等返回同一 `taskId`，随后取消；
- 原任务未创建：创建唯一任务并立即取消；
- 同键请求内容不同：服务端返回冲突，不得创建第二个任务。

只有明确的 `400/422` 请求校验失败可视为服务端未创建任务，直接完成本地取消或关闭。恢复阶段的 `401/403/404/409` 及网络、5xx、无效响应仍属于状态不确定，必须保留原幂等键和请求快照。

首次提交的规范化请求必须冻结最终 provider/model 解析结果，包括“已解析到具体目标”和“已解析为空、按智能模式走本地降级”两种状态。恢复时不得重新读取默认模型目录改变同一幂等键对应的 POST 请求体。

### 5. 外部卸载保护

父组件切换、路由变化或工作区卸载可能绕过编辑器关闭按钮。卸载时若服务端任务尚未返回标识，客户端不能立即中止初始提交；它必须保留取消意图，等待 `onTaskId` 后发出精确 DELETE。若任务标识已经存在，则卸载清理直接复用同一取消 Promise。组件卸载后不再写 React 状态，但服务端取消仍需完成。

### 6. 状态机

```text
choosing
  -> loading(submitting)
  -> cancelling(waiting-task-id)
  -> cancelling(deleting-task)
  -> choosing | closed

loading
  -> error(layering)

cancelling(waiting-task-id)
  -> error(cancel-recovery)
  -> cancelling(retry-same-key)
  -> choosing | closed
```

### 7. UI 行为

- 取消后立即显示“正在取消图片分层任务”，不虚假显示已取消。
- 关闭发生在提交期时，窗口保持可见直到服务端取消得到确认。
- 取消失败时，“重试”必须重试取消/恢复，不得开始新的付费分层任务。
- 普通分层失败时，“重试”仍创建一次新的用户尝试和新幂等键。

## 非目标与约束

- 不修改 Pear 模型选择、PSD ZIP 解析、积分价格或退款数据库规则。
- 不修改 `stable`，不写 V5.8.8 donor。
- 不以吞异常、隐藏按钮或延长等待时间规避竞态。
- 不把浏览器中止请求当作服务端任务取消。
- 云端验收前不宣称退款一致性闭环。

## 验收标准

1. 用户在 POST 响应前点击取消，收到 `taskId` 后只发送一次 DELETE。
2. 用户在 POST 响应前关闭，取消确认后才关闭编辑器。
3. 用户连续点击取消或关闭，不重复 DELETE、不创建第二个任务。
4. 响应不确定后重试取消，复用原幂等键。
5. 明确的请求校验失败不会进入恢复提交。
6. 取消失败后的“重试”不启动新付费任务。
7. PSD 分层客户端、编辑器、API、并发与账务相关回归测试通过。
8. Coze 精确提交上真实验证任务终态、单次扣费和最多一次退款。
9. DELETE 返回 `completed/failed/timeout` 时不得显示为取消成功。
10. 外部卸载发生在任务标识返回前后时，都必须对同一任务发出取消且不创建新任务。
