# V5.8.8 移动端画布选择性吸收设计

## 1. 目标与范围

本设计完成 `V588-MOBILE-001～003`：

- 无限画布支持空白区域单指平移、双指缩放与平移、图片和空白区域长按菜单。
- 选中图片后，移动端能够访问与桌面一致的全部图片工具，且浮层不越界、不被底部工具栏遮挡。
- 底部工具栏在 320px、375px 和 768px 下保持可点击、可达和无水平页面溢出。
- 新增 `/simple-create` 轻量快速生图页，复用当前登录、模型能力、生成任务、积分、项目与 AssetVersion。
- 全局和新增组件尊重 `prefers-reduced-motion: reduce`。

本阶段不实施媒体网关、协作、手绘草图转代码或 Pear 分层延期验证，不改变桌面工作区的信息架构。

## 2. 不可变约束

1. 当前 `main` 是唯一实现基础；V5.8.8 只读，不整文件覆盖 `infinite-canvas.tsx`。
2. 不修改 `stable@52f7c601ed150769e15d06fb435c6e360e28c9e7`。
3. 桌面鼠标选择、框选、图片拖动、空格平移、中键平移、滚轮缩放、批注、图片组和撤销重做保持原行为。
4. 移动端和 `/simple-create` 不建立第二套任务、积分、项目、媒体或供应商状态机。
5. 所有生成结果必须通过现有任务投影建立 AssetVersion，再进入当前项目；禁止直接覆盖旧 `projects` JSON 或只保存 localStorage。
6. 所有现有底部工具和图片工具入口必须可达，不以移动端适配为由删除或隐藏为不可访问状态。
7. 触摸事件只在画布交互表面使用 `touch-action: none`，不得阻止抽屉、表单和页面区域的正常滚动。

## 3. 方案选择

### 采用：当前画布内核加独立触摸适配器

新增无 React 状态的触摸手势控制器，仅跟踪活动 Pointer Events，并向现有 `useCanvasViewport` 输出平移、锚点缩放和长按意图。`infinite-canvas.tsx` 只负责把意图接入现有选择、菜单和视口命令。

该方案可单元测试手势状态机，并保持 `legacy/shadow/canvas-v2` 三模式继续由同一 viewport controller 比较。供体的距离、中点和长按阈值算法只作为参考，不复制其旧画布状态和页面存储。

### 不采用：在 `infinite-canvas.tsx` 内直接堆叠触摸分支

该文件已经承担大量业务入口。继续内联触摸状态会扩大闭包竞态、事件抢占和桌面回归风险。

### 禁止：整体迁移 V5.8.8 画布与 `/simple-create`

供体 `/simple-create` 直接读写 `user-data/sync?key=projects` 并以 localStorage 兜底，不能证明当前 AssetVersion、幂等、退款和跨工作区一致性，因此不得吸收其数据链路。

## 4. 触摸手势状态机

### 4.1 输入与输出

控制器输入：`pointerdown`、`pointermove`、`pointerup`、`pointercancel`，仅处理 `pointerType === 'touch'`。

控制器输出：

- `pan-start/pan-move/pan-end`：交给 `useCanvasViewport.beginPan/previewPan/commitPan`。
- `pinch`：提供屏幕坐标中点、下一 zoom 与中点位移，调用现有 `zoomAtPoint` 和视口偏移命令。
- `long-press`：提供屏幕坐标和命中目标，由画布打开现有图片或空白菜单。
- `cancel-default-interaction`：终止已开始的框选、图片拖动或单指平移，避免双指手势同时执行两个语义。

### 4.2 手势规则

- 空白区域单指按下后，累计移动达到 6px 才开始平移；开始前仍可识别点击或长按。
- 单指静止 500ms 且累计位移小于 10px时触发长按；触发后不再产生点击、拖动或平移。
- 图片单指点击保持选择；图片拖动沿用当前图片移动命令，不被空白平移接管。
- 第二指按下立即取消长按、框选和单指拖动预备态，进入双指模式。
- 双指距离控制缩放，中点位移控制平移；缩放限制继续为当前 `0.1～5`。
- 双指缩放以当前两指中点为屏幕锚点，画布内容在指下保持稳定。
- 双指减少为一指后不自动恢复图片拖动或单指平移，必须全部抬起后开始下一手势。
- `pointercancel`、窗口失焦和组件卸载必须清理所有定时器、pointer capture 和手势状态。
- 鼠标和笔输入不进入该控制器，继续执行现有桌面路径。

## 5. 移动端工具栏

### 5.1 底部工具栏

- 320px 和 375px 默认显示选择、平移、上传、缩放状态和“全部工具”五个稳定槽位。
- “全部工具”打开贴合底部栏的抽屉，复用当前工具目录、排序、隐藏偏好和原 action handler。
- 抽屉采用单层分组网格，不嵌套卡片；内容区域可纵向滚动但隐藏视觉滚动条。
- 安全区使用 `env(safe-area-inset-bottom)`；抽屉最大高度不超过可视区减去顶部 48px。
- 768px 以上保持当前桌面工具栏，不改变快捷键和折叠行为。

### 5.2 图片工具栏

- 触摸设备选中图片后，在底部工具栏上方显示紧凑动作条，而不是把桌面长工具条定位到图片上方。
- 动作条固定显示预览、下载、删除和“更多”；“更多”打开包含当前全部图片工具的底部抽屉。
- 工具清单直接来自当前 `visibleToolbarActions`，不得维护第二份功能列表。
- 打开工具面板后沿用现有 `activateCanvasToolSession`、图片身份和浮层定位，不改变任何工具业务调用。
- 抽屉、菜单、滑轨和输入框事件必须阻止画布手势；关闭后恢复画布操作。

## 6. `/simple-create`

### 6.1 页面职责

`/simple-create` 是面向手机的单列快速生图入口，包含：

- 当前会话登录检查和原入口选择页返回路径。
- 管理员授权的图像模型选择。
- 提示词、参考图、比例、尺寸、质量和数量 `1～4`。
- 每个槽位独立任务状态、逐张回填、失败原因、取消与重试。
- 最近结果预览、下载和“在画布中打开”。

### 6.2 数据与任务

- 页面通过当前模型能力目录生成可用控件，不硬编码供应商能力。
- 提交复用现有图像生成服务和持久任务合同；`n>1` 保持独立槽位和逐张回填。
- 结果由现有 task projector 建立 AssetVersion 和 Canvas placement；页面只读取返回的受管引用。
- “在画布中打开”使用当前 workspace handoff/项目路由进入相同 projectId，并定位新版本。
- 失败、取消和刷新恢复读取数据库权威终态；不得只依赖组件内 `loading`。
- 不使用供体的 `MOBILE_PROJECT_NAME`、旧 `projects` 数组覆盖或 localStorage 图片备份。

## 7. Reduced Motion 与性能

- 新增抽屉、菜单和状态切换只使用 transform/opacity，并在 reduced motion 下将持续时间置零。
- 平移和缩放使用 requestAnimationFrame 合并视图更新，不在每个 pointermove 重排全部节点。
- 手势期间继续使用现有画布虚拟化；100 节点场景不得因移动端适配关闭裁剪。
- 触摸移动不得触发页面滚动、文本选择或浏览器双击缩放；非画布页面滚动保持正常。

## 8. 错误和恢复

- 手势异常只取消当前手势，不清空选择、项目或历史。
- 工具抽屉 action 抛错时沿用现有工具错误展示，不吞掉错误或伪装成功。
- `/simple-create` 的供应商失败必须显示原始错误码、可重试性和 taskId；取消后迟到结果不得进入项目。
- 页面刷新后恢复同一 projectId、各槽位终态和已建立的 AssetVersion。
- 未登录访问时进入现有登录流程；登录成功后返回原 `/simple-create` 请求，不创建临时账号或项目副本。

## 9. 测试与验收

### 9.1 RED/GREEN 自动化

- 手势单元测试：阈值、长按、双指中点、锚点缩放、两指变一指、cancel/dispose、鼠标旁路。
- 接线测试：双指开始会取消框选/图片拖动；图片点击与拖动保持；桌面事件不进入触摸控制器。
- 工具栏组件测试：全部现有 action ID 在移动抽屉中可达，事件不穿透，安全区和无页面横向溢出。
- `/simple-create` 组件/API 测试：能力联动、`n=1～4`、逐张终态、取消/迟到隔离、AssetVersion 投影、刷新恢复与工作区跳转。
- reduced-motion CSS 和组件合同测试。

### 9.2 浏览器矩阵

- Chromium Mobile：320×568、375×667、393×852。
- Chromium Desktop：1440×900，验证鼠标、框选、空格平移、滚轮和图片工具无回归。
- Firefox 与 WebKit：375×667 核心手势、工具抽屉和 `/simple-create`。
- 真实触摸以 Pointer Events 驱动，并检查几何、hit-test、pointer capture、页面 overflow 和 Console。
- 每个项目失败保留 screenshot、video、trace、Console 和 Network；不得用固定长 sleep。

### 9.3 云端验收

- Coze 运行 exact `main`，核对源码 tree、Build ID、唯一服务和功能标志。
- 在现有受控浏览器完成：单指平移、双指缩放、长按图片/空白菜单、底部工具抽屉、图片工具抽屉。
- 使用 PearAPI 或 APIMart 完成 `/simple-create` 一次 `n=2` 真实生成，证明逐张回填、两个 AssetVersion、刷新恢复、下载和画布定位。
- 完成一次可控取消，核对一次扣费、一次退款、无迟到 AssetVersion。
- 云端无法模拟真实多点触摸时，该项必须保留为未验证，并使用实体触屏设备补验；Playwright 合成指针不能冒充实体设备手感。

## 10. 完成标准

只有同时满足以下条件才关闭 `V588-MOBILE-001～003`：

1. 所有新增测试先出现预期 RED，再由最小生产修改变为 GREEN。
2. 移动端和桌面核心回归、TypeScript、ESLint、保护基线和生产构建通过。
3. 320px、375px、768px 无工具丢失、越界、遮挡、误触或水平页面滚动。
4. `/simple-create` 的真实成功、取消、积分、AssetVersion、刷新恢复和画布打开闭环。
5. 当前全部功能入口、三个创作工作区、管理员仪表盘和用户仪表盘均未减少。
6. 更新仓库测试报告和 Obsidian 无界升级目录；只推送 `main`，不更新 `stable`。
