# V588 WebSocket 在线状态设计

日期：2026-09-24

阶段：协作能力 2/4（只读分享之后、Yjs 之前）
状态：本地实现与验证进行中；云端同源 upgrade 和正式发布尚未验收

## 1. 目标与既有边界

在已登录用户明确加入项目的前提下，画布显示当前在线参与者及连接状态。跨标签、断线、退出登录、撤销参与资格和服务重启后，状态最终收敛；不得暴露画布内容、匿名分享令牌或账务信息。本阶段只传在线状态，不传光标、画布操作或 Yjs 更新。

现有 `wujie_projects` 只有 `owner_id`，项目/资产读取按 owner 隔离；匿名只读画布分享是独立的不可变令牌资源，不能被当作项目成员资格。当前启动为 `next start`，仓库虽有 `ws` 依赖，却没有在线状态服务。`main` 的六份 `.superpowers/sdd` 用户修改保持原样，`stable` 与 V5.8.8 donor 只读。

## 2. 方案选择

1. **同源 WebSocket + PostgreSQL 租约（采用）：** 在 5000 同源 HTTP 入口处理精确 `/api/collaboration/presence` upgrade；现有 Next 页面/API 继续由 Next 处理。短时单次票据、成员权限和心跳租约都使用当前 PostgreSQL。优点是浏览器不需要第二域名或第二套身份；成本是启动脚本、容器入口和构建/重启边界需严格回归。
2. 独立端口 WebSocket：实现简单，但 Coze 预览/正式域名是否透传第二端口未获证明，且增加跨源认证和部署面；不采用。
3. 第三方实时服务：会引入第二套身份、账务/权限外部依赖；不采用。

Next.js 官方自定义服务器文档提醒其可能失去部分优化，且不能与 standalone 输出直接混用；当前工程不是 standalone。采用前须用精确当前构建验证路由、静态资源、Build ID 与部署恢复不退化。`ws` 官方 `noServer`/`handleUpgrade` 模式用于唯一在线状态路径；开发态其它升级请求必须委托 Next 的 upgrade handler，以保留 HMR，生产态未知升级请求拒绝。参考：[Next.js 自定义服务器](https://nextjs.org/docs/app/guides/custom-server)、[`ws` 官方文档](https://github.com/websockets/ws/blob/master/doc/ws.md)。

自定义入口使用 TypeScript 并以仓库已安装的 `tsx` 启动；将 `tsx` 从开发依赖转为明确的生产运行依赖，不能依赖开发镜像偶然安装。默认关闭路径仍沿用 `next start`。

## 3. 权限与参与者

- 所有者天然可加入自己状态为 `active` 的项目；非所有者须有该项目的一条有效 `presence` 成员记录。只读分享链接和管理员角色均不自动授予在线房间权限。
- 所有者可邀请已存在且启用的用户加入、列出并撤销该项目的在线参与资格。第一阶段成员权限仅为 `presence`，**不授予原画布/资产读取或编辑**；Yjs 阶段须单独设计可编辑角色与资产授权，不能沿用 presence 权限冒充编辑授权。
- 邀请使用服务端解析的精确用户身份，不接受客户端提交 `ownerId`、任意显示名或匿名分享 token 作为成员依据。跨项目、跨用户均以服务端数据库约束检查。
- 在线名单仅对当前有权加入该房间的会话返回：用户作用域标识、安全显示名、连接状态和最近心跳时间；不返回邮箱、角色、Cookie、票据、IP、项目内部素材 ID 或供应商信息。同一用户多个标签合并成一位参与者，同时保留服务端每连接租约以准确断开。
- 成员撤销、账号禁用、项目归档或所有者删除项目时，现有连接在下一次权威检查立即关闭；不能仅等 TTL。成员管理与票据签发使用现有会话认证和同源请求校验。

## 4. 连接与状态协议

1. 客户端在进入有权参与的项目后，通过 `POST /api/collaboration/presence-ticket` 获取短时、单次、绑定用户与项目的随机票据。数据库只存哈希；有效期 30 秒。拒绝跨源请求与缓存，响应不写 localStorage。
2. 浏览器以同源 `wss:`/`ws:` 连接 `/api/collaboration/presence`，票据通过 `Sec-WebSocket-Protocol` 的受限子协议值携带，不进入 URL、查询串、浏览器历史或服务日志。upgrade 前原子消费票据并复核项目权限、用户状态与 Origin；失败统一拒绝，不能泄露项目是否存在。
3. 建立连接时创建随机 connection ID，写入 `wujie_presence_leases`；服务器发完整快照及单调递增的项目事件序号。客户端只接受当前 project/connection 的快照或更大序号事件，旧项目/旧连接事件一律丢弃。
4. 心跳建议 15 秒，租约 45 秒；每次心跳复核资格并续期。正常关闭删除租约，进程崩溃由 TTL 扫除。断线采用带抖动的有界退避重连，新连接须重新取票据；页面隐藏可降低心跳频率但不伪造在线。
5. 多进程/滚动重启使用 PostgreSQL `LISTEN/NOTIFY` 作轻量唤醒、数据库租约作权威快照；通知可丢时客户端重连/周期性快照仍可收敛。只有单进程内存 Map 的实现不得作为云端通过。推送只含用户级在线状态，不含画布数据。
6. 每用户/项目限制连接数、消息长度、发送队列和心跳速率；慢客户端断开。未知消息类型、二进制帧与超限载荷拒绝。Cookie 不直接作为 WebSocket 唯一凭证。

## 5. 数据与故障边界

- 新增 `wujie_project_presence_members`：项目、所有者、成员、状态、创建/撤销时间，约束项目归属与唯一有效成员；新增 `wujie_presence_tickets`：票据哈希、用户、项目、过期/消费时间；新增 `wujie_presence_leases`：连接、用户、项目、实例、过期时间。迁移可重复执行，不改变现有项目/资产或只读分享数据。
- 项目可见性必须跟随当前画布读取模式：`legacy` 与 `shadow` 以所有者 `wujie_user_data.projects` 快照为准，`asset-v3` 才仅以资产图项目状态为准。旧版空项目可建立仅供在线资格使用的项目投影；其后正式迁移须接管该投影。旧版同步不能改名、复活或归档已正式迁移的资产图项目；即使正式项目行仍为 active，旧版快照删除项目后也要拒绝新票据/入房/续租并从在线名单移除。历史快照缺少 `userId` 或以 JSONB 字符串保存数组时仍应按 GET 兼容规则识别项目，明确标为其他用户或格式无效的项目继续拒绝。
- 功能标志 `WUJIE_PRESENCE_ENABLED` 默认关闭。关闭时不签发票据、不接受 upgrade、不运行清理 worker；现有 Next 服务、只读分享和三个工作区行为不变。数据库未配置或协作服务不可用时 UI 显示“在线状态暂不可用”，不能显示假在线人数，也不能阻断画布编辑。
- 日志仅记错误码、请求 ID 和匿名化连接计数；禁止记录票据、Cookie、原始显示名、项目内容。定期清除过期票据与租约，有界保留成员审计。
- 若 Coze/正式域名不能透传同源 WebSocket upgrade，本阶段保持 `UNVERIFIED` 并 fail-stop；不得以 SSE/轮询替代后声称 WebSocket 通过。另行评估部署代理能力，不在本阶段偷偷切换架构。

## 6. UI 与未来 Yjs 边界

- 画布项目标题区显示在线头像/人数和自己的连接状态；成员管理只对所有者开放。当前项目切换、退出登录或组件卸载立即释放连接，失败重连不重复开 socket。320–393px 窄屏使用紧凑人数入口，不遮挡现有画布工具栏。
- 节点模式和独立智能对话继续保留入口/项目同步，但本阶段不把在线状态误当作它们的实时协同编辑。后续 Yjs 可以复用成员资格检查、同源升级入口和断线测试模式，但文档 CRDT、持久化和编辑授权必须独立设计。
- 不触碰匿名只读分享页面的安全投影；匿名查看者不进入在线名单。

## 7. 验收与顺序

1. 先以隔离 PostgreSQL 和合成 socket 写失败测试：无票据、票据重放/过期、跨项目/跨用户、禁用账号、非成员、跨源、撤销、慢客户端、重复标签、断线重连、服务崩溃 TTL 和多实例通知丢失。
2. 最小实现票据/权限/租约与 WebSocket 网关，再接 UI；逐层跑聚焦、真库、完整 Vitest、类型/Lint、保护基线及干净生产构建。启动入口的回归必须覆盖普通 HTTP、静态资源、Build ID、健康端点和关闭标志。
3. 本地 Chromium/Firefox/WebKit 与窄屏验证两用户两会话在线、重连和撤销；Coze 只在 exact `main`、隔离测试账号/库和可验证同源 upgrade 下验收。正式发布还需当前目标的真实付费取消/唯一退款、GitHub Actions 和严格构建门禁，不能因 presence 单项通过而关闭。
4. 每完成一个阶段更新 Obsidian；`stable` 不改，V5.8.8 只读，不复制 donor 文件。本阶段不重做已关闭的只读分享、Stage 2/3/4 或 Skill 工作。
