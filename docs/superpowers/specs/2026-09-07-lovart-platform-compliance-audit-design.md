# Lovart 第三批平台合规检查设计

日期：2026-09-07

状态：已批准，待编写实施计划

适用分支：`main`
只读分支：`stable@52f7c601ed150769e15d06fb435c6e360e28c9e7`

## 1. 目标

在已完成的统一 Skill Runtime 和 Lovart 前两批工作流基础上，新增真实的平台素材合规检查工作流：

- Skill ID：`preset-platform-compliance-audit`
- 名称：`平台素材合规检查`
- 分类：`commerce`
- 允许入口：无限画布 AI 对话窗口、节点模式 `ai-skill`

该 Skill 接收一个或多个受管图片版本，按平台、地区、素材类型和商品分类执行确定性检查与视觉语义检查，逐张交付可追踪的结构化报告。它只检查和报告，不自动修改、删除或覆盖原素材。

## 2. 产品边界

- 无限画布中的 Skills 必须能够从 AI 对话窗口选择、补齐输入并执行。
- 节点模式使用同一 Skill 定义、输入合同、规则、模型冻结、任务和报告格式。
- 独立 `/simple-chat` 面向不同用户群体，继续保持现有 16 项专用 Skills，不显示或执行本 Skill。
- Canvas/Workflow 当前 27 项目录增加为 28 项；既有 27 项定义、顺序摘要和行为不得改变。
- 不新增底部工具栏入口，不扩大当前工具栏。
- 不使用本地 GPU。CPU 仅负责 Sharp 像素检查、规则求值、JSON 规范化和 HTML 净化。
- 视觉检查只使用管理员授权的远程视觉模型，并精确冻结 `providerId + modelId`。
- 不建立第二套任务、积分、供应商或资产状态机。

## 3. 采用方案

采用“分级判定 + 版本化规则注册表 + 通用结构化 Skill 输出”的方案。

### 3.1 分级判定

- `passed`：所有适用的必检项均有充分证据且通过。
- `warning`：存在语义、商标、认证、价格、功效或受监管内容风险，需要人工复核。
- `blocked`：可机器确定的硬性规则不符合要求，应阻止平台交付，但不阻止用户查看或导出检查报告。
- `unknown`：规则缺失、视觉模型不可用、输入不足或证据不足。`unknown` 不得折算为 `passed`。

素材不合规是正常业务结果，不是技术执行失败。网络、模型、存储、解析或数据库错误才属于技术故障。

### 3.2 未采用方案

- 所有风险均强制阻止：视觉语义存在误判，会不合理锁死用户资产。
- 仅生成自由文本建议：无法复检、筛选、按规则重跑，也不能被后续多平台导出复用。
- 运行时实时抓取平台规则网页：规则会漂移，网页可能需要登录或包含不可信内容，无法形成可审计快照。

## 4. 输入合同

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `sourceImages` | images | 是 | 1–20 个受管 AssetVersion，绑定 `sourceVersionIds` |
| `platform` | select | 是 | 通用电商、Amazon、淘宝/天猫、京东 |
| `region` | select | 是 | 根据平台动态限制；Amazon 首批支持美国、欧洲、日本 |
| `assetType` | select | 是 | 主图、辅图、详情图、A+ 内容 |
| `productCategory` | text | 否 | 服务端按已发布规则注册表规范化并校验；用于加载分类附加规则 |
| `productFacts` | text | 否 | 用户确认的商品事实，最多 4,000 字符 |
| `claims` | text | 否 | 待审核的价格、认证、功效和促销声明，最多 4,000 字符 |
| `reportLanguage` | select | 否 | 默认中文 |

服务端必须重新校验当前用户、项目、工作区和所有 AssetVersion 的归属。客户端 URL、文件路径、媒体元数据和检测结论均不是信任边界。

平台、地区、素材类型与分类必须存在于已发布规则注册表。没有对应规则时返回稳定的输入错误或 `unknown`，不得静默套用其他地区规则。

## 5. 规则注册表

每条规则至少包含：

```ts
interface PlatformComplianceRule {
  id: string;
  version: number;
  platform: string;
  regions: readonly string[];
  assetTypes: readonly string[];
  categories?: readonly string[];
  title: string;
  severity: 'warning' | 'blocking';
  evaluator: 'metadata' | 'pixel' | 'vision';
  sourceUrl: string;
  sourceUpdatedAt: string;
  effectiveAt: string;
  thresholds?: Record<string, number | string | boolean>;
}
```

规则随代码版本发布。每次运行冻结：

- 适用规则 ID 与版本；
- 规则集合摘要；
- 官方来源 URL 与来源更新时间；
- 平台、地区、素材类型和分类；
- 来源 AssetVersion 与媒体校验摘要；
- 视觉模型 `providerId + modelId`。

运行中不得自动替换规则。选择“按最新规则重新检测”必须创建新 Run 和新报告版本，旧报告保持可追踪。

首批 Amazon 规则以 Amazon 官方当前公开要求为来源，至少覆盖：支持格式、最长边范围、主图纯白背景、商品画面占比、裁切及主图文字、徽标、水印和边框限制。淘宝/天猫、京东和通用电商只纳入具有可审计来源的已发布规则；来源不足的检查项必须显示为 `unknown`，不得凭经验硬编码为平台政策。

## 6. 检测执行

### 6.1 扇出与顺序

按 `sourceImages` 原顺序编译为独立、持久的子步骤，每张图片拥有 operation、请求摘要、终态、错误、费用和报告。最大并发为 3，单张结果完成后立即投影到界面，不等待整批结束。

每张图片执行：

1. 重新授权并解析受控媒体。
2. 通过集中安全媒体读取器获取有限字节流。
3. 使用 Sharp 像素上限检查尺寸、格式、字节数、透明通道、背景颜色与背景占比。
4. 使用冻结视觉模型检查商品占比、裁切、文字、徽标、水印、道具、人物和声明风险。
5. 对视觉结果执行严格结构校验；无法证明的规则为 `unknown`。
6. 合并规则结果，生成单图报告。
7. 逐张发布进度、结论和可追踪报告。

### 6.2 不同故障的处理

- 素材违反规则：报告为 `warning` 或 `blocked`，Run 仍可正常完成。
- 视觉模型失败：先持久化并交付免费的确定性部分报告，依赖视觉证据的规则为 `unknown`，同时保留供应商错误摘要和任务身份；Run 进入可重试暂停态，不把未交付的视觉检查结算为成功。用户取消后保留部分报告，并只退款未交付的视觉费用一次。
- 图片不可读取或媒体不受信任：该图片进入可重试技术失败，不伪造报告。
- 同步视觉请求在提交后响应丢失：标记 `submission_unknown`，停止自动重试并退还未交付视觉费用；用户可显式创建新的复检版本，不在原 operation 上猜测性重放。
- 规则或报告结构无效：技术失败并保留稳定错误码。
- 单图失败：已完成图片保留；重试只重新执行失败图片，或由用户对含 `unknown` 结论的图片发起新一轮语义复检。

## 7. 结构化报告与资产

现有 Skill Runtime 只能持久化 `text/html`。本设计最小增加通用、受限的结构化输出：

```ts
interface DurableSkillJsonOutput {
  stepId: string;
  kind: 'json';
  schemaId: 'platform-compliance-report-v1';
  content: string;
}
```

要求：

- `content` 必须是规范化 JSON 字符串，不允许函数、原型键或非 JSON 值。
- 单份最大 256 KiB，最大深度 12，最大键数 4,096，最大字符串 16,384 字符。
- 持久化、事件恢复、请求摘要和客户端解析均执行相同的 schema 与边界校验。
- 原有 `text/html` 输出读取和排序保持兼容。
- HTML 阅读版由结构化数据确定性渲染，并经过现有 HTML 净化器；不得包含脚本、iframe、事件属性或不受信任外部资源。

每次运行创建新的 `document AssetVersion`。由于 Asset v3 的 `parentVersionIds` 只允许同一 Asset 内的版本链，合规文档不得把不同图片 Asset 的版本伪装成父版本；其来源通过经过授权的 `metadata.sourceVersionIds` 与 `sourceTrace` 保存。权威文件为结构化 JSON；HTML 可由 JSON 确定性导出。报告通过 Skill Run 在 Canvas AI 对话中展示，通过 Workflow 输出继续传给后续节点，不要求把文档伪装成画布图片。

报告至少包含：

- 报告 ID、Run ID、规则集合摘要与时间；
- 平台、地区、素材类型和分类；
- 每张来源 AssetVersion、文件摘要与整体结论；
- 每条规则的状态、检测器、证据、实测值、要求值、置信度和修复建议；
- 视觉模型身份、已知限制和技术错误摘要；
- 汇总数量与人工复核提示。

## 8. UI 与交互

Canvas AI 对话窗口沿用现有 Skills 搜索、输入、运行进度和历史，不增加新业务弹窗。报告卡提供：

- 整体结论、平台、地区、规则版本和检测时间；
- 每张图片的通过、警告、阻止和未知数量；
- 展开后的规则证据、实测值、要求值和修复建议；
- “只看问题”“定位画布图片”“导出 HTML”“导出 JSON”；
- “按最新规则重新检测”，创建新 Run，不覆盖历史报告。

节点模式的 `ai-skill` 使用同一输入控件和报告合同，输出端口传递 document AssetVersion 与结构化报告引用。节点可连接后续多平台尺寸和命名导出工作流。

所有状态必须使用文本、图标和颜色共同表达，不仅依赖颜色。`unknown` 必须与 `passed` 明显区分。

## 9. 模型、计费和幂等

- 本地确定性检查不收费。
- 视觉检查按实际成功调用逐张计费，执行前展示最大预估。
- 视觉模型必须由当前用户授权目录精确冻结，不得隐式降级到其他供应商或模型。
- 同一用户、Skill 版本、输入摘要、规则摘要和幂等键只创建一个 Run。
- 每张图片 operation 使用父 Run、具体步骤、来源版本和规则摘要形成唯一身份。
- 不合规是已交付检查服务，不退款。
- 供应商未成功交付视觉检查时不结算该项；确定性部分报告使用独立的零费用本地步骤持久化。取消只退尚未成功结算的视觉费用一次。
- 已知拒绝或提交前技术故障可以重试，且不得重复扣除已完成的图片或规则检查；`submission_unknown` 不自动重放。
- 迟到结果不得覆盖 `cancelled`、`failed` 或 `timeout` 终态。

## 10. 安全与可靠性

- 只读取当前 Run 已授权的 AssetVersion；不接受任意远程 URL。
- 媒体读取统一执行 MIME、字节、像素、超时和解码限制。
- 视觉模型输入不包含 API Key、令牌、无关用户数据或未选择的项目素材。
- 供应商响应按固定 schema 解析；自由文本不得直接成为规则结论。
- 平台网页内容不在运行时注入提示词或规则。
- 日志不得记录完整图片内容、访问令牌、API Key 或敏感商品资料。
- 报告错误信息保留 requestId、taskId、providerId、modelId 和稳定错误码，但敏感字段必须脱敏。

## 11. 测试与验收

### 11.1 RED 测试

实施前增加失败测试，至少覆盖：

- Amazon 平台、地区、素材类型和规则版本匹配。
- 格式、尺寸、Alpha、白背景、商品占比、裁切、文字和水印判定。
- 规则缺失、证据不足和模型失败均为 `unknown`，不默认通过。
- 不合规结果正常完成，技术故障进入可重试状态。
- 1、3、20 图扇出，最大并发 3，结果逐项返回且顺序稳定。
- 重试只运行失败图片；语义复检只针对含 `unknown` 结论的图片创建新检测版本；取消只退款一次，迟到结果被拒绝。
- provider/model 精确冻结且不存在隐式降级。
- JSON schema、深度、体积、键数、危险键和字符串长度限制。
- HTML 净化与 JSON/HTML 确定性一致。
- 新 document AssetVersion 来源正确，原图片版本、位置和文件保持不变。
- Canvas/Workflow 目录为 28，原 27 项摘要不变；Simple Chat 保持 16 且不含新 Skill。
- 刷新恢复报告、规则版本、逐图状态、错误与费用。

### 11.2 回归门禁

- 聚焦单元、API、组件和客户端恢复测试通过。
- 使用一次性隔离 PostgreSQL 验证并发幂等、单次结算、部分退款和迟到终态。
- 当前 Skill Runtime、前两批 Lovart、AssetVersion、Canvas、Workflow 和 Simple Chat 保护测试通过。
- TypeScript、构建版 ESLint、全仓测试、保护基线和生产构建退出 0。
- `stable` SHA 保持 `52f7c601ed150769e15d06fb435c6e360e28c9e7`。

### 11.3 云端真实验收

Coze 精确拉取候选 `main` 并重启沙箱、刷新现有预览页后：

1. 在 Canvas AI 对话窗口选择至少三张受管图片运行 Amazon 主图检查。
2. 证明报告逐张出现，硬规则、视觉风险和 `unknown` 区分正确。
3. 核对冻结的视觉 provider/model、最大预估、实际扣费和失败不重复扣费。
4. 在 Workflow 运行同一 Skill，并将结构化报告连接到下游节点。
5. 下载 JSON 与 HTML，刷新页面后恢复相同报告、规则版本和来源关系。
6. 取消一个进行中批次，证明只退款未完成视觉检查一次且迟到结果不覆盖终态。
7. 验证 Simple Chat 仍为 16 项，Canvas/Workflow 为 28 项，原有 Skills 和入口无丢失。
8. 保存截图、Console、Network、事件、document AssetVersion 和积分流水证据。

无法安全制造或缺少供应商条件的场景必须写入 `UNVERIFIED_ITEMS.md`，不得以本地夹具冒充云端通过。

## 12. 非目标与后续

本规格不包含：

- 自动修图、自动白底化或自动改写商品声明；
- 自动上传 Amazon、淘宝/天猫或京东；
- 平台账户授权与刊登管理；
- 法律意见、商标授权结论或监管认证；
- Brief 到视频成片；
- 多平台批量尺寸和命名导出；
- 独立 Simple Chat Skills 改造；
- 本地 GPU、OCR 训练或新的供应商任务状态机。

本项关闭后，Lovart 第三批按顺序继续：

1. 多平台批量尺寸和命名导出；
2. Brief 到视频成片完整链路。
