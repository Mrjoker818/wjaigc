# Skill 需求与交付上下文修正设计

状态：2026-09-04用户已确认，进入实施。当前源码基线main@8237f5b6；不得更改stable。

## 目标与证据

修复已在Chrome真实复现的需求丢失：用户输入草莓蛋糕，规划内容正确，成品却是面食。只修正现有运行内核的数据契约，不增加新目录、模型或收费边界。

- 生产适配器只编译当前promptTemplate。
- 21个预设从旧对话迁入，assistant示例被当作成品指令，未必包含任何参数。
- executor保存上游outputs，但不向后续步骤传递。
- continuation恢复冻结定义时systemPrompt为空、inputs为空。
- 已有2项RED：输入strawberry cake/restaurant menu，实际提交只有render。

## 方案比较

1. 修改21个模板：改动直观，但自定义Skill及暂停恢复仍可能丢失上下文，且容易把业务文案作为修复补丁，不采用。
2. 在每次调用时读取最新目录和历史会话：数据较全，但违背运行冻结和恢复幂等，同一任务可能随目录变化而改变，不采用。
3. 冻结执行上下文并显式传递已完成前序结果：推荐。初次与恢复使用相同数据，沿用现有任务、事件、版本与扣费系统。

## 推荐边界

### 新任务冻结

为新任务保存带版本号的执行上下文契约，包含Skill身份/版本、系统指令、输入字段定义、已校验输入值及步骤。必须进入既有冻结事件与请求摘要约束，不允许仅依赖进程内数据。

未带新契约标识的历史任务不静默改写提示词或请求摘要；已完成任务只读，旧暂停任务不自动重试。旧任务恢复须明确保持旧契约或提示以新任务执行，不可在同一幂等身份下替换请求内容。

### 步骤上下文

每一步接收本次运行冻结的用户需求及已完成的前序步骤输出。用户明确输入优先，规划作为参考，不允许assistant示例替代用户需求。

并行步骤只读取进入并行组之前的已完成结果，同组兄弟及未来步骤输出不可泄露。恢复使用数据库事件中属于当前run的持久化结果，不读取其他run或最新目录。

上下文采用确定性排序与序列化。步骤摘要覆盖实际参与请求的上下文及契约版本；同样输入与相同前序结果摘要相同，结果变化则摘要变化，禁止错误重放。

只将文本型需求和受控文本输出写入提示词。图片/Brand Kit/数据集继续走现有授权资产引用，不能把base64、对象存储凭据或任意整包数据拼入提示词。大小超限显式拒绝，不静默截断核心需求。

### 生成与质量

编排模型接收冻结系统指令、用户需求和前序上下文。图像生成接收真实需求与已完成规划，而不是只有“我来生成……”的对话示例。

保留现有output-present门禁，同时明确它只证明有结果，不证明内容符合需求。真实验收必须核对主体、数量、风格及画布独立节点；不得把此次修复宣称为已经具备通用视觉语义质量检测。

### 不修改内容

不更改Stage4资产归属检查、登录、供应商选择、积分扣除或退款规则；不让21个画布/节点Skill出现在独立智能对话16个Skill目录中；不把图片引用降为无授权URL。
