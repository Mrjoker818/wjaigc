# 草图创作双模式设计

用户于 2026-10-13 明确确认默认草图生图、保留草图转代码。本文补充原 `2026-10-09-sketch-to-code-design.md`，不改写其 HTML 安全合同或已验历史。

## 用户流程

入口改称“草图创作”。默认“草图生图”，另有“草图转代码”。绘图历史、8色、3档粗细、撤销、重做、清空及原始 PNG 导出继续共用。图像模式的输入说明为创作关键词，而非页面布局专用说明。

草图生图使用两组明确的 `providerId + modelId`：视觉分析 LLM 与图像生成模型。视觉模型须为支持视觉的同步 chat-completions 聊天模型；图像模型须为 image、支持至少一张参考图及 image-to-image 操作（若目录声明操作），输出含 image。不按模型名猜能力，不自动选首个供应商，不回退为纯文生图。

服务受理前冻结项目、原始 PNG、关键词、两个模型绑定及图像参数，并检查两组授权和能力。实际图像请求必须携带同一原始 PNG；分析文字不能代替参考图。视觉分析输出须为受校验 JSON：`summary`、`composition`、`prompt`、`negativePrompt`，不得把任意模型原文当有效结果。用户关键词与有效分析共同构成图像提示词，参考描述来自本次分析，不另触发隐式视觉模型。

图像成功结果必须有当前项目的受权资产版本与任务身份，预览、下载、添加消费同一结果。原始草图不被结果替换。HTML 模式仍只接受白名单界面树、空 sandbox 与受权文档读取，保持原受理/取消/退款合同。

## 任务、计费与失败边界

计算合同不是任务权威或发布许可。运行接入须复用已有 durable task、幂等、执行租约、取消信号、原始账务及资产发布设施；不得使用浏览器串联两个无恢复的付费请求作为最终实现，也不新增内存任务 Map。费用必须区分本次视觉分析与图像生成，不能免费跳过分析或重复向子生成扣费。

模型权限被撤销、项目切换或授权代次变化后不能继续下一阶段或放置结果。不明受理、供应商回执丢失、账务提交不明、取消后的迟到成功必须停在核对状态；没有持久化屏障不得标为完成或重提交。单阶段失败保留草图及已确认阶段证据，退款只能依据原账务权威确认。

两个模式保留各自选项及任务结果。切换模式只是显示投影，不自动提交、不清空绘图、不取消已受理任务；关闭窗口仍只停止读取。刷新恢复只使用受权的持久任务/资产，不信任本地缓存结果作为发布证明。

## 验收与范围

先验证不可变合同、模型筛选、真实 PNG、分析 JSON、两模型冻结、实际参考图与参数；再验证原任务/账务/资产接入和故障窗口；最后接入 UI/节点与当前构建。所有行为先失败测试再最小实现，不削弱旧断言或超时。新默认入口必须在运行接入和失败路径就绪后启用，不能上线可点击但无法运行的空壳。

交付检查之后才正常提交并同步 GitHub main，由 Coze 拉取；项目页核对源码 tree、BUILD_ID 和完成标记，再在新独立 Edge 预览页验收。真实付费、S3 和实体触控未取得证据应明确未验证。第七项延期、Pear 取消和 PSD 核心保留，不正式部署。
