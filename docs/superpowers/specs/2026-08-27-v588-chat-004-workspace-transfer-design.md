## 2. 背景与目标

当前独立智能对话页面已经能够把受管理图片发送到无限画布，但缺少完整的来源追踪，也不能把消息中的文本和图片可靠地发送到节点模式。V5.8.8 提供了通过 `localStorage` 传递原始文本和图片 URL 的实现参考，但该方案缺少用户归属校验、跨项目授权、幂等控制和刷新恢复，不直接吸收。

本项以现有 `AssetVersion -> /api/assets/transfer` 资产链路为基础，增加一个由服务端解析的工作区交接协议，使用户可以把一条智能对话消息发送到无限画布或节点模式，并保留消息、项目、模型、供应商和生成任务来源。

## 3. 范围

### 3.1 本项包含

1. 在智能对话消息操作区提供“发送到节点模式”入口，并复用当前“目标画布”项目选择。
2. 使用受限标识跳转到目标项目的节点模式，不在 URL 或 `localStorage` 中传递原始文本、图片 URL 或完整消息对象。
3. 由登录态服务端接口读取当前用户的权威 Simple Chat 快照并解析指定消息。
4. 将消息文本创建为 `input-text` 节点，将每个可管理图片创建为独立 `input-image` 节点。
5. 通过 `/api/assets/transfer` 把图片版本转移到目标项目和目标工作流，保持项目归属、资产版本和幂等约束。
6. 无工作流时自动创建稳定标识的“智能对话导入”工作流；已有工作流时只追加节点，不替换已有节点或连线。
7. 在画布图片和节点属性面板中显示简洁的智能对话来源信息。
8. 在刷新、重复消费、跨项目、普通用户和保存失败场景下保持可恢复、不可重复和不可越权。

### 3.2 本项不包含

1. 不引入永久数据库交接队列。
2. 不重构 Simple Chat 消息存储、画布内核或整个工作流引擎。
3. 不复制 V5.8.8 的 `wujie_node_bridge` 原始 URL `localStorage` 方案。
4. 不允许导入仅有外部 URL、缺少受管理资产引用的历史图片。
5. 不改变现有聊天、画布、节点模式的核心业务入口和现有功能。

## 4. 设计原则

1. **服务端权威解析**：客户端只提交标识，消息内容和图片资产引用由服务端根据当前登录用户重新读取。
2. **资产链路复用**：图片继续使用现有资产版本和 `/api/assets/transfer`，不建立旁路上传或直接抓取外部图片。
3. **幂等优先**：工作流标识、节点标识和资产转移键均可确定计算，刷新或重复点击不能创建重复节点或重复资产。
4. **保存后消费**：交接参数只在目标工作流持久化成功后清理；保存失败时保留参数，允许刷新后重试。
5. **最小侵入**：在现有组件和持久化接口上增加小型、可单测的交接模块，不扩大到无关功能。

## 5. 数据模型

新增共享来源类型 `WorkspaceSourceTrace`，由画布图片、工作流节点配置和规范化资产引用共同使用：

```ts
export interface WorkspaceSourceTrace {
  source: 'simple-chat'
  chatProjectId: string
  chatTaskId: string
  messageId: string
  modelId?: string
  providerId?: string
  generationTaskIds?: string[]
  agentRunId?: string
  createdAt: string
}
```

规则：

- `chatProjectId`、`chatTaskId` 和 `messageId` 是来源定位必填项。
- `modelId` 与 `providerId` 来自消息实际执行信息，不使用界面当前选择值覆盖。
- 图片生成事件已知供应商任务标识时写入 `generationTaskIds`。
- `sourceTrace` 只保存标识和审计元数据，不保存提示词正文、图片二进制、API Key 或 Token。
- `/api/assets` 返回规范化引用时只公开经过类型校验的 `sourceTrace`，不透传任意 placement metadata。

## 6. 交接协议

### 6.1 客户端跳转意图

智能对话页面生成仅含受限参数的节点模式 URL：

```text
/?projectId=<targetProjectId>
  &mode=node
  &chatProjectId=<sourceChatProjectId>
  &chatTaskId=<sourceChatTaskId>
  &chatMessageId=<sourceMessageId>
```

所有标识必须满足现有项目和任务标识长度、字符集限制。URL 不包含文本正文、图片 URL、图片 data URL 或序列化消息。

### 6.2 服务端解析接口

新增登录态接口解析交接意图。接口读取当前用户的 Simple Chat 权威快照，按来源项目、任务和消息三层定位目标消息，并返回经过裁剪的交接载荷：

```ts
interface SimpleChatWorkspaceHandoff {
  text: string | null
  images: Array<{
    imageIndex: number
    assetRef: WorkspaceAssetReference
    sourceTrace: WorkspaceSourceTrace
  }>
  sourceTrace: WorkspaceSourceTrace
  warnings: Array<'UNMANAGED_IMAGE_SKIPPED'>
}
```

接口必须验证：

1. 用户已登录。
2. 来源聊天项目、任务和消息归属于当前用户。
3. 目标项目存在且归属于当前用户。
4. 图片引用与消息图片按索引严格对齐，且资产版本属于当前用户。
5. 标识非法、资源不存在和越权访问返回统一的 400、404 或 403 业务错误。

## 7. 工作流行为

### 7.1 目标模式初始化

`CanvasWorkspace` 在存在 `projectId` 且 `mode=node` 时直接进入节点模式，不先进入无限画布再切换，避免界面闪烁和错误的画布副作用。

### 7.2 无现有工作流

目标项目没有工作流元数据时，自动创建：

- 名称：`智能对话导入`
- ID：由目标项目 ID 通过固定、可重复的规范化函数计算
- 初始节点：仅本次交接产生的文本和图片节点
- 随机 ID 禁止用于该自动创建场景

同一目标项目在刷新、重复进入或并发消费时计算出相同工作流 ID。

### 7.3 已有工作流

目标项目已有工作流时：

- 保留原工作流 ID、名称、节点、连线、视口和配置。
- 只在可用区域追加新节点。
- 不删除、不重排、不覆盖任何已有节点或连线。
- 已存在相同确定性节点 ID 时跳过该节点。

### 7.4 节点构造

- 文本节点类型：`input-text`
- 图片节点类型：`input-image`
- 节点 ID：由来源项目、来源任务、消息 ID、负载类型和图片索引确定计算
- 节点配置：包含可见内容和 `sourceTrace`
- 图片节点 URL：使用资产转移后由 `/api/assets` 解析出的规范化受管理 URL
- 节点位置：基于现有节点包围盒，在右侧空白区域按稳定网格排列；重复消费不能改变已有节点位置

## 8. 图片资产转移

每张图片调用现有 `/api/assets/transfer`：

```ts
{
  sourceVersion: sourceAssetVersionId,
  targetProject: targetProjectId,
  targetWorkspace: stableWorkflowId,
  entityType: 'workflow-input',
  entityId: deterministicNodeId,
  idempotencyKey,
  metadata: {
    sourceTrace,
    imageIndex
  }
}
```

幂等键至少绑定目标项目、目标工作流、来源项目、来源任务、消息 ID、图片索引和来源资产版本。相同键不同请求摘要仍按现有资产服务规则返回冲突。

跨项目转移只能由资产服务在验证当前用户同时拥有来源资产和目标项目后完成。普通用户不获得管理员能力，也不能引用其他用户的项目或资产。

## 9. 历史图片和非法 URL

1. 只有存在受管理、索引对齐 `imageRef` 的图片才能进入工作流。
2. 只有原始外部 URL、data URL 或缺少资产版本的历史图片槽位不进行网络抓取，也不创建图片节点。
3. 消息同时包含文本和不可管理图片时，文本仍可导入，并显示“部分历史图片缺少受管理资产，已跳过”的明确提示。
4. 消息只有不可管理图片且没有文本时，交接失败并保留 URL 参数，用户可以返回智能对话重新生成或上传。

## 10. 来源展示

### 10.1 节点模式

选中导入节点后，属性面板在常规字段上方显示只读来源区：

- 来源：智能对话
- 对话项目
- 模型与供应商（有值时）
- 来源消息时间

来源区不显示内部 Token、API Key、完整请求体或敏感提示词。

### 10.2 无限画布

通过智能对话导入的图片在选中状态的信息区域增加紧凑的“智能对话”来源标识，并在悬停说明中提供来源项目、模型和供应商。现有模型/供应商标签继续保留，不新增遮挡图片操作的浮层。

## 11. 持久化、恢复与并发

交接执行顺序固定为：

1. 解析 URL 中的受限标识。
2. 调用服务端解析接口获取权威消息。
3. 确定或创建稳定工作流 ID。
4. 对受管理图片执行幂等资产转移。
5. 构造确定性文本和图片节点，并跳过已存在节点。
6. 调用现有工作流持久化流程保存完整项目元数据。
7. 服务端保存成功后清除交接 URL 参数。
8. 显示成功、部分成功或失败状态。

若步骤 3 至 6 中断：

- URL 参数保持不变。
- 刷新后重新执行相同流程。
- 已转移资产由幂等键复用。
- 已持久化节点由确定性 ID 去重。
- 不覆盖用户在此期间新增的其他节点。

## 12. 错误处理

- `400 INVALID_HANDOFF`：参数非法或消息内容不可导入。
- `401 UNAUTHORIZED`：登录失效，沿用当前登录恢复流程。
- `403 FORBIDDEN`：来源或目标资源不属于当前用户。
- `404 HANDOFF_SOURCE_NOT_FOUND`：来源项目、任务或消息不存在。
- `409 HANDOFF_CONFLICT`：幂等键对应的请求摘要冲突，停止消费并保留参数。
- `422 NO_MANAGED_MEDIA`：没有文本且所有图片均不可管理。
- `500 WORKFLOW_SAVE_FAILED`：工作流保存失败，保留参数并提供重试。

错误提示必须面向用户说明失败阶段，不吞掉服务端错误，也不把失败交接标记为成功。

## 13. 测试门禁

### 13.1 单元和接口测试

1. URL 只包含受限 ID，不包含文本或媒体 URL。
2. 稳定工作流 ID 对同一项目重复计算一致，不同项目不同。
3. 文本和图片节点 ID 确定、稳定且不碰撞。
4. 无工作流时创建“智能对话导入”。
5. 已有工作流只追加，不覆盖节点、连线或视口。
6. 当前用户跨自己的两个项目转移成功。
7. 其他用户来源项目、目标项目和资产引用全部拒绝。
8. 非法 URL、data URL、缺失资产版本被跳过或拒绝，且不触发远程抓取。
9. 重复消费只生成一组节点和一组资产转移。
10. 保存失败时不清理 URL；刷新后可以恢复。
11. 规范化资产引用返回经过校验的 `sourceTrace`，不泄露任意 metadata。
12. 普通用户可以操作自己的项目，但不能获得管理员权限。

### 13.2 浏览器回归

1. Simple Chat 文本消息发送到无工作流项目，节点模式直接打开并出现一个文本节点。
2. 图文消息发送到已有工作流，原节点不变，新增文本和图片节点。
3. 刷新页面后节点和来源信息仍存在。
4. 重复点击发送或重复刷新不产生重复节点。
5. 历史非托管图片显示部分跳过提示，文本仍导入。
6. 非法或越权标识不能导入任何数据。
7. 无限画布原有“添加到画布”链路继续工作，并显示来源标识。
8. Chromium 核心流程通过；Firefox 与 WebKit 至少完成交接核心回归。
