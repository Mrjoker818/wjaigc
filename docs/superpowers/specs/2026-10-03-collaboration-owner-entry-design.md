# 协作项目所有者入口设计

## 定位与边界

本设计落实既有 `2026-09-25-v588-yjs-canvas-collaboration.md` Task 8D 的 owner 启用、邀请、撤销及 editor 进入项目要求，不新增独立协作系统，也不关闭 Task 8C、8D、8E 或发布验收。

保留画布、节点、独立对话及全部旧入口；共享项目不得复制到编辑者私人项目列表。任务、扣费与退款保持当前执行者身份，素材和结果版本继续由现有资产图与文档管理。Pear 专项按 2026-09-27 范围决定排除，PSD 核心保留。

## 已核实的现状

- `project-actions-menu.tsx` 只有重命名、导出、管理分享和删除，没有协作管理入口。
- `document-enable` 只有 POST，依赖所有者及 `expectedRevision`，启用后文档成为权威；不能从客户端直接覆盖文档。
- `editors` 提供 GET/POST/DELETE，授权当前使用内部 `memberUserId`。
- 画布已有 `?projectId=` 深链及 `document-project` 受邀读取路径，不需要再创建一个项目副本。
- `enableCollaborativeProject` 的 `inspectManagedMedia` 仅检查图片，视频返回 null。是否能复用已有就绪资产须由用例区分；不得笼统把所有视频都判为可启用或不可启用。

## 方案选择

采用项目菜单“管理协作”对话框，接入现有服务端权限和文档接口。比独立协作仪表盘更贴近已有项目操作，也避免让用户输入内部用户 ID 的开发调试式入口。无需新增站点导航或改造全部仪表盘。

## 用户链路

1. 所有者打开项目菜单中的“管理协作”。读取该项目的启用状态与服务能力，不自动迁移、不自动启用。
2. 未开启功能时说明协作不可用；状态加载失败可重试，不能据失败推断未启用。
3. 用户选择启用时，先等待当前项目保存完成。使用保存返回的实际项目 ID 和同步修订号调用启用接口；保存失败不得继续。
4. 修订冲突时刷新项目和状态，保留明确提示，不盲目重复迁移或覆盖服务器数据。启用成功后读取服务端项目，更新修订号与文档权威状态。
5. 已启用时显示当前编辑者列表。输入现有登录账号名称邀请，服务端完成身份解析与授权；不展示密码、API Key 或内部用户 ID 输入框。
6. 撤销按选中成员的内部 ID 调用现有接口，成功后重新读取列表；网络结果不确定时读回状态，不把未知结果显示成成功。
7. 复制含 `projectId` 的登录访问链接。受邀者登录后进入原项目；该链接不是匿名分享凭证，没有授权的用户仍被拒绝。

“管理分享”继续提供既有只读分享。协作启用不新增退回旧快照的关闭开关，避免绕过已有权威隔离。

## 服务端合同

### 状态查询

为 `document-enable` 增加只读 GET，查询参数只允许一个合法 `projectId`。使用会话身份读取本人项目；未迁移的旧项目仍可查询。返回 `success`、`projectId`、`featureEnabled`、`enabled`、`currentRevision`。

查询不得创建资产、文档、任务或修改修订号。启用记录存在而文档缺失等不一致应返回权威冲突，不能伪装成未启用。停用服务能力仍允许所有者读取状态。401、403、400、409、500 分别表示未登录、无权限、无效请求、权威冲突、内部失败；响应 private/no-store，Vary Cookie。

### 邀请

POST `/api/collaboration/editors` 保留已有 `{projectId, memberUserId}` 合同，同时支持严格互斥的 `{projectId, memberName}`；DELETE 仍只接受内部 ID。两种邀请入口使用同一权限与授权代次规则。

服务端在授权事务内先验证所有者及项目，再按登录账号的现有精确匹配规则查找 active 用户。禁止自行小写账号改变身份规则；重复名称不能取第一项，须明确拒绝。不存在、停用、重名或本人账号均不授权；不开放用户搜索或全站账号枚举接口。名称错误返回统一的可邀请账号无效提示；重复邀请保持幂等，撤销后重新邀请沿用原授权代次规则。

保留来源验证、JSON 大小/类型限制及当前用户会话；非所有者请求不能通过账号解析泄露成员信息。新增按名称邀请仅在已启用且权威完整的项目上生效；旧内部 ID 入口保留所有者启用前配置授权的既有合同，不扩大其文档读写权限。是否允许实际文档读写仍由原启用、权限与代次检查决定。

### 视频预检

保留已有图片严格检查，补足视频受管来源的真实字节检查及元数据读取。复用现有二进制媒体 MIME、格式、大小和受管路径限制，不信任客户端提供的后缀、宽高或字节数，不把任意远程 URL 当受管文件。

媒体 I/O 在事务及授权锁外进行，最终迁移事务重新验证所有者、快照修订、来源身份与资产一致性。就绪资产、待迁移受管视频、缺失视频及混合图像/视频分别验收。错误时全项目启用原子失败，保留原素材，不悄悄跳过视频或以占位图替代视频。

## 客户端边界

协作对话框独立于大型仪表盘组件，复用现有 Dialog、项目菜单与“管理分享”的焦点恢复方式。提供清晰加载、错误、重试及单项操作状态；防止重复提交，剪贴板失败不得显示已复制。

异步回调绑定当前用户、项目和对话框打开代次；切项目、退出登录、关闭或重新打开后，迟到响应不得修改当前界面或私人项目列表。保存后项目 ID 映射必须传入启用及链接生成，不能使用旧临时 ID。

## 验收证据

- 真实路由与 PostgreSQL：状态只读、旧项目状态、非所有者拒绝、重复/未知查询参数、停用能力、权威缺损；名称邀请唯一匹配、自邀/停用/重名拒绝、旧 ID 合同、并发邀请、撤销与重新授权。
- 启用迁移：就绪图片/视频、待迁移有效视频、混合项目、损坏/缺失/越界视频、修订冲突及并发启用；拒绝后零文档变更、原文件与账本不变。
- 组件行为：真实菜单入口、保存完成前不启用、保存后的 ID/修订号、失败与不确定结果读回、跨用户/跨项目迟到回调、复制失败、键盘及焦点恢复。
- 双账号浏览器：通过界面启用和邀请，不预置授权代替；编辑者从链接进入，双方读到同一版本，撤销后拒绝继续编辑，私人项目列表不新增副本，旧分享仍只读。
- 同项目画布、节点及独立对话版本读回必须另以真实流程证明，不能用授权接口绿灯替代三工作区互通验收。
