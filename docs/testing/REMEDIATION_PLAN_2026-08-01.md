# 无界 AI 缺陷修复与回归计划（2026-08-01）

## 目标

将当前版本从“**不通过**”推进到可再次进入发布验收的状态。以下顺序按 P0 → P1 → P2 执行；每个步骤均要求先写稳定失败测试，再修改最小代码，最后在稳定部署做真实浏览器复测。

## 阶段 0：先补可观测性与测试边界

### 0.0 立即处置管理员凭据泄露

对应：AUD-20260801-041。

- 立即轮换已登录管理员与任何可能受影响测试账号的密码、会话和刷新令牌；检查审计日志是否存在新建用户表单加载、异常创建或敏感请求。
- 新建用户表单在打开时强制 reset 为全空状态；用户名/邮箱禁止继承当前登录用户；密码必须 `autocomplete="new-password"`，且不得在 DOM、日志、持久化草稿或提交 payload 中携带当前管理员凭据。
- 在隔离环境以一次性管理员账号建立浏览器、组件和 API 回归；测试证据只保留脱敏字段状态。

验收：任何浏览器、任何已登录状态下，新建用户表单用户名/邮箱/密码均为空；无法从 DOM、日志、网络或表单草稿读取当前会话凭据。

### 0.1 管理后台主数据与审计统一

对应：AUD-20260801-042、043。

- 统一用户、积分账户、内容资产、项目、操作日志和支付订单的服务端查询路径；仪表盘、列表与汇总不得分别从 localStorage、内存缓存和不同表的非关联数据读取。
- 每个生成、编辑、项目 CRUD、用户管理与支付审核操作在服务端事务中写入审计事件，关联匿名用户/用户 ID、操作、时间、状态、requestId/taskId；敏感字段必须脱敏。
- 规范订单时间字段和迁移策略；前端只接收 ISO 或明确的 epoch 单位，格式化失败必须安全降级。

验收：同一刷新后的后台各页面显示一致用户总数；实际操作实时或在明确延迟内进入日志；订单时间无 `Invalid Date`，能可靠进行对账。

### 0.1 统一任务终态证据

覆盖 `/api/generate`、`/api/image-edit`、`/api/edit`、`/api/image-to-3d`、工作流和 ChatCanvas。

- 每个任务持久化 `taskId`、`requestId`、`userId`、`providerId`、`modelId`、`status`、`progress`、`errorCode`、`retryable`、扣费与退款流水。
- 终态只允许条件转换：`processing -> completed|failed|cancelled|timeout`；终态之间不得覆盖。
- 前端处理卡片必须在成功、失败、取消、超时四种情况保留明确结果；禁止 catch 后仅移除 processing 卡片。
- 取消调用应中止客户端请求，并将后端任务置为可审计终态。

验收：人为制造 400、429、500、非 JSON、断网和取消时，页面不使用阻塞 `alert`，不永久 loading，不静默消失，不重复扣费。

### 0.2 测试基础设施修正

- 修正 `E2E_ENABLE_PAID_GENERATION=1` 与 `true` 的解释不一致。
- 删除测试代码中的登录凭据回退，改用 CI secret 和隔离测试帐号。
- 将 CRLF 敏感断言改成结构化或换行无关断言。
- 为 Playwright 添加移动端项目；补充真实文件上传和下载事件能力。
- 修复安全测试的 429 断言与付费请求保护，限制可花费次数和目标项目。

验收：CI 能清晰证明是否实际执行了付费 P0；失败时上传 trace、video、screenshot、Console 和网络日志。

## 阶段 1：无限画布与图片编辑 P1

### 1.1 画布移动与撤销

对应：AUD-20260801-019、020、034。

- 画布图片拖动：跟踪 `pointerdown -> pointermove -> pointerup -> image position state -> persistence`，用同一坐标系断言位置已变。
- 画布撤销：删除动作前保存快照，按 `Delete -> Ctrl+Z -> Ctrl+Shift+Z` 做端到端回归。
- 节点撤销：`src/components/node-editor.tsx:994-1047` 在首个变更前写入初始快照；不要只修改 `idx <= 0` 判断。

验收：图片移动、节点新增/删除/连线/属性变更第一次起就能 undo/redo，刷新后项目最终状态一致。

### 1.2 擦除、蒙版、去背景

对应：AUD-20260801-021、024、036。

- 追踪共享数据流：`selected image URL -> ImageEditPanel image onload -> canvas coordinate transform -> maskDataUrl -> /api/image-edit -> task registry -> result node`。
- 针对 `/api/serve-upload/*`、CDN URL、data URL 分别建立受控输入测试，确保编辑器实际显示源图。
- 对导出的掩码用 Sharp 读取像素；真实画笔后必须存在非零白色编辑区域。
- `fetch('/api/image-edit')` 捕获网络异常、超时、非 JSON 和业务错误时，写入明确失败状态，不允许移除处理卡片。
- 去背景失败不得停留在 12%；成功产物必须验证 PNG alpha，不得用棋盘格视觉假象代替透明通道。

验收：擦除/蒙版成功产生独立结果节点；任何失败显示原因、可重试动作和 requestId；没有重复扣费或悬挂任务。

### 1.3 调色与面板层级

对应：AUD-20260801-023。

- 将固定 `right: 40px` 的调色浮窗纳入可协调的 overlay 管理，而不是与右侧聊天面板竞争层级。
- 修复 `/api/image/color-adjust` 返回路径、错误解析、成功结果写入画布和刷新持久化。

验收：聊天面板打开时仍能触达调色控制；提交后一定产生变更后的结果或明确失败。

### 1.4 图片浮动工具栏边界与放大任务

对应：AUD-20260801-039、040。

- 为图片工具栏实现基于 viewport 的边界约束：锚点靠近左、右、上、下边缘时平移或翻转，所有可见控制必须处在可点击范围内。
- 放大 UI 必须显示当前实际模型或提供明确的“自动选择”决策结果；管理员配置的 302 放大模型应由能力元数据驱动可选项，而不是被隐藏。
- 把 302 的审核拒绝、参数错误、限流、超时和网络错误转换为统一可重试/不可重试错误对象；禁止 `alert`，并使 processing 卡片进入可审计终态。

验收：画布任意边缘的图片工具都可操作；至少一个已授权 302 放大模型完成 4K 结果；上游失败不阻塞界面、不留悬挂任务，积分状态可追溯。

## 阶段 2：元素拆解、PSD 与透明输出 P1

对应：AUD-20260801-025、026，以及 Pear 分层 ZIP/PSD 真实部署验证。

- 以真实白底源图建立“主体 PNG 必须含 alpha=0 像素”的图像断言。
- 对 `display_decompose` 的自动去背景失败，禁止将不透明原图标记为“透明主体”；应返回降级标志与真实原因。
- PSD 编辑器的图层可见性状态必须驱动 compositing canvas 重绘；全部隐藏时画布应透明。
- Pear 分层链路继续验证异步任务、ZIP MIME、主 PSD 提取、depth PSD 忽略、PSD 图层编辑、取消与退款。

验收：主体层透明、背景层可独立开关、重新合成可视觉还原原图；导出的 PSD/PNG 可被外部工具读取。

## 阶段 3：Agent、工作流、3D 与提供商闭环 P1

### 3.1 Agent 与工作流

- Agent `analyze_image` 404：按“工具选择 -> 请求 URL -> 认证/受控图片读取 -> route handler”追踪，禁止工具失败后继续声称有图像上下文。
- 节点 AI 建图：为默认渠道 500 建立 provider health、备用模型选择、可重试及 requestId 显示。

验收：至少一条真实图片分析和一条三节点 AI 建图可完成；上游失败显示可诊断信息而非假成功。

### 3.2 图转 3D

对应：AUD-20260801-035。

- 检查 `src/components/infinite-canvas.tsx:8049-8143` 及 `/api/image-to-3d` 的请求体、源图可访问性、302 响应和任务创建。
- 不得将 HTTP 500 映射为浏览器 `alert`；返回标准错误结构与 requestId、provider/model、是否扣费、可重试状态。

验收：已授权默认模型完成一个最小真实任务；失败、取消、超时均有一致任务和积分终态。

### 3.3 提供商与模型能力

- 对每个启用模型建立合同矩阵：比例、像素尺寸、质量、数量、参考图、图生图/编辑、视频时长。
- 真实验证路径必须记录 UI 选择、实际请求体、提供商 taskId、返回文件元数据和积分流水。
- 4S 协议验证失败、旧项目聊天模型为空、长 processing 任务未收敛分别处理；不可用提供商应明确下线或显示不可用状态。

验收：用户永远无法在 UI 选到当前模型不支持的参数；`n>1` 任务与结果数一致，失败可追溯。

### 3.4 视频任务终态与时长能力

对应：AUD-20260801-037、038。

- 追踪“生成视频”从提交、任务注册、SSE/轮询、上游结果解析到画布视频节点创建的每一段；所有分支都必须写入明确终态，禁止仅卸载 processing 卡片。
- 对 AIlink、APImart、Pear 的已启用视频模型建立时长能力矩阵，显示和提交同一份受控档位；支持 15 秒的模型必须暴露 15 秒，模型不支持时须显示上限和原因。
- 将视频 result URL、尺寸、时长、provider/model、taskId、requestId 与积分流水写入任务审计记录；失败、取消、超时按条件终态完成。

验收：一条最小真实文生视频产生可播放节点；失败/取消/超时不静默、不丢卡片；所选模型的 UI 时长、请求参数和上游限制完全一致。

### 3.5 人物精修与精修引擎可执行性

- 人物精修大师应从当前画布图片建立受控输入，但还必须向当前用户/管理员解析可授权的图像编辑模型；空模型列表时明确说明授权缺失，不得只留下禁用按钮。
- 精修引擎提交后必须创建可见任务状态；从“开始精修”到请求、provider/model、taskId、进度、结果或失败都需要可观测。禁止点击后无任何反馈。
- 分别用真实人物和非人物输入覆盖检测、局部蒙版、候选结果、保存到画布、取消和失败退款；非人物应显示适当限制而不是伪造修复成功。

验收：管理员在有已授权模型时能完成最小真实人像修复；没有授权时能看到明确配置路径；精修引擎每次提交都有可追踪终态。

## 阶段 4：安全、支付、发布门禁

- 处理 `pnpm audit` 中的 10 high / 5 moderate；升级 Next.js、Sharp、SVGO、ExcelJS 等受影响依赖后执行安全回归。
- PostgreSQL 中用用户维度唯一键和规范化请求摘要实现任务幂等；完成、取消、超时和退款采用原子条件更新。
- 真实支付、积分扣除、退款和管理员定价使用隔离环境验证，日志不得包含密码、完整 token 或 API Key。
- 添加运行时错误关联：version、commit、requestId、taskId、provider、model、用户匿名会话。

验收：P0=0、P1=0、真实核心 E2E 100%、跨 Chromium/Firefox/WebKit 与移动端核心链路通过，全部未验证项完成或明确从发布范围移除。

## 重新验收顺序

1. 阶段 0 的测试和任务终态观测先落地。
2. 阶段 1 修复后立即跑图片编辑与画布回归。
3. 阶段 2、3 各自完成真实提供商闭环和扣费/退款检查。
4. 阶段 4 后从干净环境运行 `npm ci`、`npm run doctor`、`pnpm lint`、`pnpm ts-check`、`pnpm test`、`pnpm test:api`、`pnpm test:regression`、`pnpm build`。
5. 最后才在稳定部署执行登录、上传、生成、保存、刷新恢复、下载、退出登录的真实浏览器验收。
