## 审计结论

采用“薄网关门面 + 当前权威内核”进行选择性吸收，不复制 donor 的协议包，不迁移 donor 的任务状态机。媒体网关对外负责密钥、限流、日配额、请求幂等和审计；图像/视频提交、轮询、取消、积分、退款、AssetVersion 与供应商适配继续由当前线负责。

## 当前线事实

1. 图像权威入口为 `/api/generate`，已经包含精确 `providerId + modelId`、模型能力准入、`n>1` 分槽、持久化任务、积分和 AssetVersion 投影。
2. 视频权威入口为 `/api/video/generate`，已经包含任务核心、模型能力、取消、终态竞争、积分和 AssetVersion。
3. `/api/poll-task` 已支持内部鉴权和持久化任务恢复；`/api/cancel-task` 当前仍使用 Cookie 会话，需要在不削弱普通用户权限校验的前提下补充受信内部鉴权。
4. 当前 `src/lib/api-compatibility.ts` 与 `src/lib/video-api.ts` 已经分别比 donor 包版本产生 `102/45` 和 `94/27` 行差异。整体替换会覆盖当前修复。
5. 当前已经存在 `wujie_asset_thumbnail_variants`，支持 `256/512 WebP`、`FOR UPDATE SKIP LOCKED`、处理租约、失败重试、安全图片输入、像素/字节上限、S3 优先和持久数据根回退。多尺寸缩略图不应重复建设。

## Donor 可吸收内容

- 独立 `wmg_` 网关密钥，数据库只保存 SHA-256 哈希和安全前缀。
- `GATEWAY_ENABLED` 默认关闭、显式开启。
- `/api/gateway/v1/images` 与 `/api/gateway/v1/videos` 作为外部门面，使用受信内部身份转入现有生成入口。
- 网关来源标签、用户归属、操作日志与配额概念。

## Donor 不可直接吸收内容

1. `packages/wujie-media-gateway` 复制了旧版 `api-compatibility.ts` 和 `video-api.ts`。当前仓库不是 pnpm workspace，抽包会扩大结构变更并产生第二份协议真相。
2. Pear 图像 profile 固定 `task_type: sync`。这对普通同步图片可能是既有兼容行为，但不能作为网关统一策略，更不能覆盖 Pear 分层的异步 ZIP 链路。
3. donor 所称“rate limit”实际只有 `quota_daily/used_today`，没有时间窗口限流。
4. donor 先递增计数，再以普通减一退款；没有请求幂等唯一键、请求摘要或条件式结算，并发重试可能重复占用或重复返还。
5. donor 只提供提交入口，没有网关身份下的任务查询和取消闭环。
6. donor 没有可用的密钥创建、吊销、配额调整管理面；其文档也明确只能手工 SQL 操作。
7. donor 通过请求体写入 `sourceChannel=gateway`，但当前线生成路由不读取该字段。直接复制后不会产生可信账务标签，而且普通请求体字段也不能作为可信来源证明。
8. donor 仅按内部 HTTP 状态判断成功。HTTP 200 但业务失败、没有 taskId 或部分提交时，配额状态可能错误。

## 推荐架构

### 1. 控制面

- 管理员签发、列出、调整配额和吊销网关密钥；原始密钥只在签发成功时显示一次。
- 密钥绑定真实用户，生成入口继续执行该用户的模型授权、积分余额和数据隔离。
- 数据库保存密钥哈希、前缀、标签、启停、分钟限额、日配额和审计时间，不保存原始密钥。

### 2. 请求准入

- 分钟限流统计所有尝试，不因失败返还，防止恶意重试绕过限流。
- 日配额统计成功进入现有持久化任务系统的请求；参数校验失败或未创建任何任务时条件式释放。
- `gatewayKeyId + idempotencyKey` 建唯一约束，并保存规范化请求摘要；同键同摘要返回同一任务，同键异摘要返回 `409`。
- `n>1` 仍由当前生成批次创建多个真实槽位；网关只占一个外部请求配额，积分继续按当前模型与输出数量计算。

### 3. 数据面

- `POST /api/gateway/v1/images` 转入 `/api/generate`。
- `POST /api/gateway/v1/videos` 转入 `/api/video/generate`。
- `GET /api/gateway/v1/tasks/{taskId}` 从当前持久化任务读取状态和结果。
- `POST /api/gateway/v1/tasks/{taskId}/cancel` 复用当前取消与原子退款逻辑。
- 网关不保存第二份任务状态，只保存外部请求到权威 taskId/taskIds 的关联和配额结算状态。

### 4. 可信来源与可观测性

- 网关使用受信内部请求身份传递 `gatewayRequestId/gatewayKeyId`；生成路由仅在内部身份验证成功时接受这些字段。
- 任务、积分流水和操作日志记录网关来源、请求 ID、providerId、modelId、耗时和终态，不记录原始密钥或供应商 API Key。
- 对外错误采用稳定错误码并保留 `requestId`；供应商原始敏感内容不得直接泄漏。

### 5. 缩略图

- 复用现有 `256/512 WebP` 变体、回填 API、S3 和画布投影，不新增第二张表或第二套 worker。
- 本阶段只补充网关结果读取与永久回归，证明按目标尺寸选择变体、失败后回退原图，不重新实现图像处理。

## 备选方案

1. **薄网关门面（推荐）**：改动最小，直接复用当前成熟任务/积分/资产系统，最符合“不建立第二套状态机”。
2. **先抽取当前协议层为 workspace 包**：长期模块边界更清晰，但当前会同时修改数十个导入和构建配置，回归面过大，应在网关稳定后单独实施。
3. **整体迁移 donor 网关**：速度表面最快，但会覆盖当前协议修复、缺失管理面和真实限流，并引入账务/任务双轨，拒绝采用。

## 实施拆分建议

- `MEDIA-001A`：密钥控制面、原子限流/日配额/幂等预留。
- `MEDIA-001B`：图像/视频提交、状态查询、取消与可信账务标签。
- `MEDIA-001C`：现有缩略图变体接入与回归验证。
- `MEDIA-001D`：隔离 PostgreSQL 并发、API 安全、全量门禁和 Coze 关闭态/开启态验收。

以上四项按顺序完成，每项先 RED、再最小实现、再扩大回归；完成前保持 `GATEWAY_ENABLED=false`，不触碰 `stable`。
