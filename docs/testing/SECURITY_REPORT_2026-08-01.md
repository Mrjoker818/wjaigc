## 认证与测试凭据

- 多个 E2E/API 测试在源码中保留账号/密码回退值。实际账号是否仍有效不在本轮通过登录尝试验证，但这已违反秘密管理原则。
- 必须立刻轮换该测试账号，删除源码回退值，改为只使用 CI Secret 或未跟踪的本地环境文件。
- 登录相关真实浏览器测试已存在，但 P0 付费开关编码不一致，导致真实 P0 CI 当前不能完成。详见 `AUD-20260801-014`。
- **新增真实 P0：** 管理员打开“添加用户”表单时，用户名与密码字段自动预填当前管理员凭据（`AUD-20260801-041`）。未执行创建操作，面板已关闭；为了不扩散秘密，未保留包含字段值的截图或日志。该问题应视为即时凭据泄露，先轮换受影响管理员密码，再修复表单初始化与 `autocomplete` 策略。

## 远程输入与文件处理

静态扫描检出多个服务端远程 URL 读取点，覆盖视觉识别、矢量化、图像编辑、3D、品牌电商、导出、缓存和视频帧等路径。已知 Pear 图层路径使用了安全下载与 ZIP/PSD 限制；其余路径不能从本次 grep 结果直接推断为同等安全。

`/api/cache-image` 是当前可直接定位的不一致点：它仅拦截部分字面内网主机名/IP，随后使用默认重定向策略下载 URL；没有复用 `safe-image-download.ts` 的 DNS 解析后地址校验与受控重定向。该项记录为 `AUD-20260801-R07`，本轮没有对云端或第三方地址实施攻击性验证。

后续安全验证必须逐端点确认：

1. 只允许 `http/https` 或受控平台媒体路径。
2. DNS 解析后拒绝私网、保留地址、回环地址与重绑定。
3. 禁止未经重新验证的重定向。
4. 强制 MIME、解码后大小、像素数、压缩包条目数和路径上限。
5. 将所有 Sharp、SVG、视频、PSD 输入纳入统一的安全包装器。

目前不能对所有远程图片读取路径宣布“SSRF 已关闭”。

## 任务与积分一致性

- 批注、元素拆解已有数据库条件式终态与退款并发测试。
- 普通图像生成仍使用未带状态前置条件的通用终态更新路径，缺少等价 PostgreSQL 竞争测试。
- 该项记录为 `AUD-20260801-R06` 静态高风险，不等同于已确认的重复扣费事故；在真实数据库竞争验证前不得把“只扣一次、只退一次”标记为通过。

安全测试自身还存在两项门禁风险：

- 连续错误登录测试要求 10 次都返回 `401`，但当前登录路由在 5 次失败后按设计返回 `429`；而 `test:http-api` 会在同一 Vitest 运行中加载所有 `tests/api` 文件，另一个核心 API 测试也对同一账户做 5 次错误登录。有效限流既会被测试误判为失败，也会造成文件间状态污染。
- 多个注入测试直接向 `/api/generate` 发送 `submitOnly` 请求，若真实提供商已配置，可能创建任务或产生费用。

因此 `pnpm test:http-api` 在修复 `AUD-20260801-018` 前不能作为“安全扫描无副作用且通过”的证据。
