## 2026-08-01 白盒风险补充

普通图像生成的终态持久化与积分退款未完成和批注/元素拆解同等级的 PostgreSQL 并发验收。静态检查显示其通用终态记录可不受 `processing` 前置状态限制地更新任务；这不是已确认的线上扣费事故，但在真实并发测试完成前，发布结论必须保留该可靠性风险，详见 `AUD-20260801-R06`。

## 发布前必须完成

1. 修复全部 P1，并为每项建立稳定的浏览器或 API 回归测试。
2. 完成新旧项目下的上传、选择/移动/缩放/删除、生成、保存、刷新恢复、下载闭环。
3. 对 4S、Pear、APIB、AI Link、302 的已启用模型分别完成“UI 参数 → 后端请求 → 供应商任务 → 结果文件/积分流水”验证。
4. 处理任务超时、取消、退款和长期 processing 的最终态收敛。
5. 在扣子项目页沙箱断开后的自动恢复流程中复跑核心 E2E。
6. 修复真实 P0 CI 付费开关契约，轮换测试账号并移除源码凭据回退值。
7. 受控升级 Next.js、Sharp、SVGO、brace-expansion 依赖树并完成安全回归。
8. 修复 HTTP 安全测试的限流契约与付费调用风险，再运行完整安全/API 回归。
9. 完成 Firefox、WebKit、移动端和 PostgreSQL 并发测试。
